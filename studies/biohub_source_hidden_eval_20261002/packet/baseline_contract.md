## 手法契約

- input: x138が固定した2つの公開画像モデルと公開トラッカー、train画像20動画、各動画の疎なGEFF正解中心。x138の検出点で中心と6近傍から224次元の特徴を保存する。
- target / objective: フレーム内で検出点と既知正解中心を物理距離7 µm以内の一対一対応にし、正解中心までの3軸物理座標差を学習する。未対応検出点を偽陽性とみなさない。
- output: `Linear(224,32) -> SiLU -> Linear(32,3)` の3軸補正。作者の `bounded` 関数によりノルムを2 µm未満へ制限し、入力特徴の学習側平均・標準偏差もcheckpointへ保存する。
- loss: 3軸補正と正解残差のHuber損失。画像モデル、公開トラッカー、候補生成・接続・分裂復号は更新しない。
- decode: 補正量を検出座標へ加え、x138の三線形特徴補間、graph構築と後処理へ渡す。
- context unit: 座標補正は検出点、教師対応は同一フレーム、学習と検証の分離は動画、最終graphは動画。
- 実装区分: 参照構造と推論処理を保ち、独自の教師対応・loss・学習条件を加える `staged-faithful`。この語はこのリポジトリ内の実装管理用語。作者のcheckpointや0.953を再現したとは主張しない。
- 変更class: `mechanism`。exp042の固定作者checkpointによる推論から、自前の位置補正学習を追加する。
- 同じ親で連続した小改善実験ではなく、取得不能な重みの補完と中心誤差という別の予測対象を実装する。`kaggle-idea-forge`による探索は今回の具体的な依頼に不要。

## 実装方法

- 公開x138のNotebook SHAとコードセルを確認してから、セットアップと画像特徴抽出・推論部分を同じ順でNotebookへ含める。変更するのはtrain動画選択、V1284の`capture` mode、独自の学習・評価、学習済み重みへの参照。公開3 checkpointはSHA検査を維持する。
- 20動画は画像ファイル名の安定したハッシュで胚 `44b6` と `6bba` から各10本選ぶ。正解を見て動画を選ばない。最初の各胚1動画を同じNotebook内で予備確認し、capture時間を測ってから残りを処理する。予備確認は独立実験や精度判定ではない。
- 20動画の特徴・教師を一度だけ抽出する。動画単位の5分割で補正なしとの中心距離を比較し、各胚の動画数、対応件数、改善・悪化動画数と距離を報告する。公開画像モデルはこのtrain集合で学習済みなので、独立したCVとは呼ばず固定公開モデル下の条件付き比較とする。
- 5分割の評価が終わったら20動画全体で最終headを1個学習する。checkpointは `state_dict`、`mean`、`scale` の作者の読込形式を守り、SHAと入力版をmanifestへ保存する。
- 最終headをprivate Kaggle Dataset `kentookumura/exp043-self-trained-coordinate-head`へ置き、別の推論Notebookが実ファイルのSHAを検査してからx138のpublic test 4動画へ組み込む。公開構成の後処理まで実行し、`submission.csv`の形式・行数・SHAを記録する。これは提出ではなく、公開testは正解がないため公式scoreも計測しない。
- active variantは自前head 1、構造と設定は1、学習済み公開モデルの再学習は0、5分割の小型headを評価用に学習、boosterは0。補正なしの対照は保存済み座標から計算し、親モデルをGPUで再学習しない。
- Kaggle T4 2基、オフライン、Notebook上限12時間、週45GPU時間の範囲で実行する。push直前にquotaを確認し、予備確認の実測から残りの見込みを計算する。見込みが3時間のcapture予算またはNotebook上限を超えるときは残りを開始せず費用と原因を記録する。

## 成功条件と停止条件

- 成功条件: 特徴224次元と座標単位を確認し、20動画の教師対応と動画単位の条件付き評価、各胚の結果、checkpointとmanifest、x138 public test推論の出力検査が揃うこと。精度向上と公式scoreは観測前に仮定しない。
- 停止条件: 公開artifact SHA不一致、特徴次元・座標単位不一致、GEFF読込不整合、学習対応が不足、NaN、予算超過、推論失敗。失敗時は別のモデルや閾値探索に無断で切り替えない。
- 実行しないこと: 作者重みとの同一性や0.953再現の主張、公開testを教師や設定選択に使用、未対応候補の負例化、公開画像モデルまたはトラッカーの再学習、実際のcompetition submission、ユーザー判断前の完了・採用status。
- 未決事項: なし。件数、精度、所要時間はKaggle実行時に確認する事項。

## 探索幅とpivot判定

- 同じ入力特徴とモデル構造で、学習設定1件、動画単位の評価5分割、最終head1個とする。補正なしは座標から計算し、親モデルの再学習は行わない。

## 再現性・リスク

- 動画選択とfold割当は安定したSHAで固定し、PyTorch学習のseedを固定する。CUDA推論、ILP、Kaggle環境の完全な決定性は仮定しない。
- 公開画像モデルが199 train動画を学習済みのため、headの動画単位評価を独立したCVとは呼ばない。公開testには正解を使わない。
- 動画ごとの特徴内容SHA、head SHA、Notebook SHA、Kaggle kernel version、推論出力SHAを記録する。特徴抽出は20動画で再実行が必要で、exp015の旧cacheはx138の特徴と同一ではない。
- captureの予備確認後に3時間予算を超える見込みなら残りを始めない。実測の全体所要時間とGPU quotaは別に記録する。
