
# CELL 0
## 📖 What is this competition about?

Imagine watching a 3D movie of a zebrafish embryo under a microscope. 
But this isn't ordinary cinema — **each frame is volumetric, not flat**.

Think of it as a layered cake with 64 slices, and hundreds of glowing cells floating in every layer. 
Your job is to trace the fate of **every single cell** from the beginning of the movie to the end.

---

### 🎯 Three main tasks

| Task | What to do | Real-life analogy |
|------|-----------|-------------------|
| 🔍 **Detect** | Find all cells in a frame | Find all glowing marbles in murky jelly |
| 🔗 **Track** | Link cells across frames | Figure out that the marble in frame #5 is the same one from frame #4 |
| 🌳 **Lineage** | Spot division events | Notice when one marble splits into two |

---

### 😤 Why is this hard?

- **Thousands of cells**, all looking identical — like tennis balls in a crowd
- They **move, deform, and divide** during filming
- Images are **noisy** — not all cells are clearly visible, some hide
- Annotations are **sparse** — scientists labeled only a fraction of cells, 
  total count is a mystery (hint: check `estimated_number_of_nodes`)

---

### 📊 How are solutions scored?

The metric has **two components**:

| Component | Weight | What it measures | Plain English |
|-----------|--------|-----------------|---------------|
| **Edge Jaccard** | ~85% | Quality of cell-to-cell links | Did you connect the right cells with arrows? |
| **Division Jaccard** | ~15% | Quality of division detection | Did you find where a mother cell split into two daughters? |

**Final score** = weighted sum of the two Jaccard metrics.

💡 **Gotcha:** Due to the formula, the metric **can exceed 1.0**!

---

### 🧠 Key insight about the metric

> Cell coordinates are compared in **physical space** (microns), 
> not in voxels. Scale: `z=1.625 µm/voxel`, `y=x=0.40625 µm/voxel`.

This means a 1-voxel error in Z ≠ a 1-voxel error in X/Y. 
**XY centroid accuracy is 4× more important** than Z!

---

### 📁 Input data

- **4D video:** shape `(T=100, Z=64, Y=256, X=256)`, `uint16` format
- **Storage format:** Zarr v3 (modern format for large arrays)
- **Dataset size:** 87.61 GB, 199 training videos + hidden test set
- **Train/Test split:** by embryo (one embryo won't appear in both train and test)

---

### 🏆 Output format

A CSV file with a graph of two row types:

| Row | Description | Example |
|-----|-------------|---------|
| **Node** | Cell with ID and coords (t, z, y, x) | `node, 1, 0, 32, 128, 128` |
| **Edge** | Link between cells (source_id → target_id) | `edge, -1, -1, -1, -1, -1, 1, 2` |

Where:
- **Node:** *"Cell #1 at frame 0 is at position (z=32, y=128, x=128)"*
- **Edge:** *"Cell #1 from frame 0 is the same cell as #2 in frame 1"*

## 🧩 Pipeline components

- **TemporalUNet3D** — cell detector in 3D+time
- **Node Transformer** — edge scoring between neighboring frames
- **ILP solver** — global lineage graph reconstruction
- **DeepCenter + TTA** — veto gate for reconstructed nodes with 8-view augmentation
- **Dual-seed ensemble** — primary + secondary (seed 314159)
- **Harmonic bidirectional fusion** — forward/reverse via harmonic mean
- **PPSWEEP** — automated post-process parameter sweep

# CELL 12
## 6. Постобработка графа и создание submission.csv

Финальный конвейер: загружает `.geff`, применяет цепочку постобработчиков и пишет `submission.csv`.

**Что делает по шагам:**

- `graph_from_geff` — загрузка графа.
- `read_test_frame` — чтение 3D-кадра из Zarr (blosc2 fast path, fallback на zarr).
- `refine_synthetic_midpoint` — уточнение координат восстановленного узла по локальному центру масс.
- **DeepCenter veto** — `_DCDeepCenterUNet3D` + TTA по 8 views проверяет gap-узлы и safe-div кandidates.
- **Motion relink** — двухпроходная венгерская оптимизация (tight 6µm / relaxed 10µm) с учётом скорости.
- **Gap closing** — восстановление пропущенного кадра между треками t и t+2, адаптивный порог по плотности (cKDTree).
- **Gap2 recovery** — восстановление через 2 кадра с 3 рёбрами и проверкой контекста движения.
- **Safe divisions** — вторая дочка добавляется при mutual NN + divergence + symmetry-tau.
- **Short-track filter** — удаление компонент короче 6 узлов (кроме делений).
- **Linefit smoothing** — сглаживание координат внутри линейных треков без изменения топологии.

**`filter_output_graph`** — главный постобработчик, последовательно вызывает всё выше.

**Запись submission** — для каждого графа: узлы + рёбра, с проверками на dangling edges и покрытие датасетов.

В конце — `write_test_submission("base")`.

## 7. Аудит сабмита и отчёта о frame-retention guard

Независимая label-free проверка `submission.csv` и логов `retention_guard_*.jsonl`. Не меняет предсказания — только валидирует.

**Этапы:**

1. **Схема CSV** — колонки, непрерывность `id`, только `node`/`edge`.
2. **Покрытие датасетов** — сверка с `.zarr` в `TEST_DIR`.
3. **Retention guard логи** — нет дубликатов, все фильмы покрыты, `minimum_retention=0.9`, корректность `use_primary`.
4. **Топология** — `t ≥ 0`, координаты неотрицательны, `target = source_t + 1`, `indegree ≤ 1`, `outdegree ≤ 2`, счёт `division_parents`.
5. **Диагностика по фильмам** — frames, fallback_frames, min/median retention.
6. **Отчёт** — `dual_seed_frame_retention_guard_report.json` с SHA256, топологией, diagnostics, quality_promotion.

# CELL 18
## 9. Валидатор: расчёт официальной метрики

Считает официальную метрику на отложенных train-видео из Cell 8. Не влияет на итоговый `submission.csv`.

**Основные функции:**

- `match_nodes_bipartite` — сопоставление pred↔GT по кадрам, венгерский алгоритм, порог 7 µm.
- `compute_edge_confusion` — TP/FP/FN по рёбрам. TP — оба конца совпали с GT и между ними есть GT-ребро.
- `edge_jaccard` — TP / (TP + FP + FN).
- `adjusted_jaccard` — штраф за перепредсказание узлов относительно `estimated_number_of_nodes`.
- `weakly_connected_components` — компоненты без учёта направления.
- `compute_division_confusion` — патч организаторов: одна компонента должна покрывать обе дочерние линии + якорь + развилка.
- `decompose_errors` — разбивка ошибок: missed, spurious, recovered, fragmented, lost_to_detection, wrong_association.
- `read_estimated_true_node_count` — извлекает `estimated_number_of_nodes` из `.geff`.
- `score_sample` — метрики одного видео.
- `aggregate_official` — итог: `adjusted_edge_jaccard + 0.1 * division_jaccard` (PROXY_SCORE).

**Важно:** перед `filter_output_graph` глобально подменяется `TEST_DIR` на `TRAIN_DIR` (DeepCenter veto читает кадры через этот глобал), после — восстанавливается.

Итоги пишутся в `validator_results.csv`.

# CELL 24
## 12. Pipeline Manifest — проверка фактического состояния

Финальная отладочная ячейка. Ничего не считает и не меняет — только печатает реальное состояние механизмов в рантайме, а не то, что декларировано в конфиге.

**Что проверяется:**

- **Dual-seed** — найден ли файл secondary-весов. Если нет — warning о fallback на single-seed.
- **Bidirectional fusion** — weight, active, mode.
- **DeepCenter veto** — requested vs loaded, путь к чекпоинту, epoch, флаги gap veto и safe-div veto. Если запрошен, но не загружен — предупреждение, что veto'ы no-op.
- **Safe-div thresholds** — parent, sister, global_cap, frame_cap.
- **Validator** — enabled, held_out_samples, match_radius.

**Зачем:** последний рубеж контроля. Если скор подозрительный — сюда смотрят первым делом, чтобы понять, реально ли работали механизмы.
