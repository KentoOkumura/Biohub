# 仮説生成のためのデータ探索

予測を作る前から、実際の入力とラベルを見て解き方を探す。保存済みの誤差分析は`kaggle-oof-readout`へ渡せるが、そのためだけに新たな学習を始めない。

## 探索範囲

`project.yml.data`と公式データ仕様から利用可能な入力を確認する。既存の集計・図・サンプルが同じデータ版と対象範囲を扱っていれば再利用する。新たに見るデータ範囲と、探索を区切る作業時間枠または確認範囲を先に決める。これは作業の上限であり、実験の所要時間予測ではない。

仮説がまだなくても、無作為に選んだ実例と集計から観察を始める。発見の有無だけを理由に探索を延長しない。最初の探索後に分析を追加するときは、その結果によって実験の入力・教師・出力・評価または着手判断の何を変えるかを示す。

## 見る対象

データに合う観点を選ぶ。網羅や全図表の作成は不要。

- 生の入力とラベルを対応させた実例。画像なら画像、文章なら原文など、集計だけで失う構造を見る。
- ラベルの作成・収集・欠測の仕方と評価対象。未注釈を負例とみなせるかを確認する。
- 個体、群、時間、空間の依存関係、重複、欠損、単位や変換の整合性。
- 分布の端、少数クラス、群間差、入力と教師の不一致など、無作為例と対比できる実例。
- 現在のモデルが使っていない入力や、前処理で捨てる情報。推論時にも使える範囲を確認する。

集計で見つけた傾向を実例で確かめ、印象的な実例だけから頻度や一般性を主張しない。観測、解釈、仮定を分ける。検証用データの反復利用と公式ルールの制約を明示し、提出用データの教師を仮定しない。

## 仮説への接続と再利用

重要な観測から、どの入力・教師・表現・推論方法を変えれば何を判別できるかを考える。現在のモデルの失敗例だけを発想源にせず、データ構造や別分野の手法からの案も残す。

記録には、データ版・対象範囲・抽出方法、実際に見た実例や集計への参照、観測と限界を残す。その場限りの表・図・コードは`studies/`、完了した分析は`docs/surveys/`へ置く。実験固有の分析は既存の実験記録へ参照を追加し、同じ結論を重複保存しない。

入力・教師・評価の前提が変わった場合や、既存の観測では説明できない結果が出た場合に再探索する。実験ごとに同じEDAをやり直さない。生データにアクセスできない場合は、資料だけでの仮説生成であることを明示し、EDAを実施済みと記録しない。
