# BiohubのILPと最終グラフ選択を学習する改善案

ユーザーの問いは「接続候補と最終グラフの改善として、ILPを学習モデルで置き換える案はあるか」。本調査は変更位置と案の比較であり、実装・改善効果・採否を確定しない。

- 対応する上位仮説: `HYP-20260910-11`, `HYP-20260910-12`

支持・棄却は判断しない。[既存のグラフ直接予測案](biohub-direct-graph-learning-ideas_20260921.md)に対し、今回はexp043の後段も含めて置換する箇所を調べた。

## 結論

ILP（整数線形計画法）を学習した選択へ置き換える案はある。現在の証拠から先に比較したいのは、**接続と分裂の得点を共有し、既知注釈に整合するグラフが、既知の誤りを含むグラフより高得点になるよう学習する方法**。最初の比較ではILPを保持すると、得点の改善と解法の変更を分けられる。

ILPを使わない方法として、候補グラフ上で情報を交換して接続を選ぶモデルや、合法な接続変更を順に選ぶモデルを検討できる。後者をexp043の最終段に追加するなら「後処理の学習化」であり、前段ILPを置き換えたことにはならない。

## 前回答の数値が示す範囲

[exp015](../../experiments/exp015_oracle_stage_limits/result.md)の既知中心対応99.286%、候補graph内の既知edge94.829%、最終graph内91.602%は、既知注釈に対して失われる接続がある証拠である。中心とedgeは分母が異なる。これらの差を公式scoreの改善幅、ILP単独の誤り、現行exp043の上限と解釈しない。

[exp043 source](../../experiments/exp043_x138_self_trained_head/exp043_x138_self_trained_head_inference.py)を確認すると、1367行付近でILPを実行するが、3658行以降で残ったedgeの得点を収集し、3671行以降で運動情報による再接続と未使用点回収を行い、成功すれば接続集合を置き換える。2258行付近では後段に未登録の学習得点は0になる。

そのため、前段で接続得点が改善しても後段へ効果が伝わるかを測る必要がある。全候補得点を保持し、未評価・候補外と低確率を区別する入力も検討対象。詳細は[exp043再評価](biohub-exp043-tracker-reassessment_20260924.md)を参照。

## 学習対象を分けた3案

| 方法 | 入力・出力・損失 | 推論と最小検証 |
| --- | --- | --- |
| 選択されるグラフを考慮して費用を学ぶ | 固定画像特徴、座標、検出得点、周辺候補から接続・分裂・開始終了の得点を出す。既知注釈に整合するgraphと競合graphの得点差を学ぶ | 同じILPで選択。学習側の小規模な分裂が1娘だけの候補より高得点になるか確認 |
| 接続の選択自体を学ぶ | 候補グラフ上の情報交換から接続や分裂を出力し、既知の対応を学ぶ | 制約を満たす解への投影、または選択肢maskを伴う逐次生成。親子数違反、順序依存、誤接続を検証 |
| 最終グラフの修正を学ぶ | 現行graph、未使用候補、固定特徴から、変更なし・親変更・接続交換・分裂組追加・候補点回収を採点する | 競合修正をまとめて選ぶ。短時系列で直した既知edgeと壊した既知edgeを別集計 |

母Aから娘B・Cへの分裂なら、通常接続にも使うA→B、A→Cの得点に、BとCが同じ母の娘として整合するかの得点を加える。正しい2本が、片方だけ残すgraphや誤った親へ接続するgraphより高くなるよう学習する。単純加算で全母が2娘になる退化を避け、出次数や接続なしも比較する。

小さなニューラルネットワークや、候補グラフに沿って情報を交換するグラフニューラルネットワーク（GNN）が実装候補。モデル名より、教師・損失・合法な出力の定義を先に決める。

## 過去実験との差

[exp028](../../experiments/exp028_direct_graph_prediction/result.md)の娘ごとの親直接選択は、両胚で観測可能な誤接続率が対照のおよそ2倍。44b6の分裂回収増加はあるが通常接続の悪化が残った。同じ構成を再実行する根拠とはしない。

[exp029](../../experiments/exp029_mother_daughter_set_selection/result.md)では候補内の正解2娘128件全てが自己1娘・空集合より低得点。全候補を残した整数最適化でも分裂回収0件で、学習内の分裂117件も0件だった。正しい分裂を合法な高得点の自己部分集合へ置き換えられるため、**同じ得点をより正確に最適化するだけでは回収できない**。

共有接続得点、分裂損失の寄与、グラフ間の直接比較はこの失敗に対応する変更だが、効果は未測定。[shared_edge_graph_learning](../../experiments/exp050_shared_edge_graph_learning/requirements.md)にも一部記録済みで、新規発案とは扱わない。具体的な損失と内部モデル選択は実装前に確定する。

## 比較する5案

| 案 | 期待する効果 | 最小検証・停止条件 |
| --- | --- | --- |
| 共有得点とグラフ比較 | 候補内の接続・分裂を選ぶ | 小規模の既知分裂も学べなければ大規模学習へ進まない |
| 同動画の運動と画像の信頼度を学ぶ | 近傍移動が外れる領域を補う | 同候補で固定融合を上回らないなら止める。参照不足時は画像側へ戻す |
| 画像・距離・近傍運動による候補保持 | 早期に落とす正解を回収する | 同候補数で回収が増えない、または誤接続だけ増えるなら止める |
| 実予測の誤りを模した事前学習 | 誤った中間graphを修正する教師を増やす | 実予測だけの同容量学習を上回らず、合成内だけ改善するなら止める |
| 同一edgeの段階別追跡 | 学習する位置と最終段への伝達を確認 | 入力が一致しない比較から原因を断定しない |

[12案の詳細JSON](../../studies/ilp_learning_alternatives_20260924/idea_portfolio.json)には、合法な局所修正、複数graphの順位学習、短軌跡の可逆圧縮も保存した。12案の同時実装を推奨するものではない。

## 教師・検証・未解決事項

- 未注釈の接続を一律負例にせず、既知1娘を「第2娘なし」の正解にしない。注釈と両立する複数graphを許す。候補とGTの対応が曖昧な例も扱いを分ける。
- 修正モデルには可能なら下流モデルの学習から外した対象の予測を入力する。2胚しかないため内部予測の作り方を明示する。公開画像重み由来の条件付き評価はこの分割でも解消しない。
- 候補内に正解がある割合と、それを選べる割合を分ける。後段編集では操作集合に正しい修正があるかを先に調べる。
- 隣接2-frameで測れる変更は先に単体比較。後処理・欠落補完は短い時系列で診断し、窓境界と修復・破壊の両方を確認する。
- 学習側内部で方式を固定し、両胚の接続・観測可能誤接続・分裂を確認。進行条件を満たした場合にKaggle上で全graphと公式評価器を実行する。単体診断を公式scoreと扱わない。
- 方針は公開画像側固定、Kaggleのみ、offline推論12時間。週次GPU枠と例外は[現在方針](../../backlog/KAGGLE_DIRECTION.md#今後の学習方針)を正とし、過去資料の数値へ戻さない。
- exp043の全候補得点、train段階別graph、現在の残量、反復solver費用は未取得・未実測。必要な保存と対照を最初の改善実験へ含める。
- 採否・完了はユーザー判断。調査後の依頼で下記3案をバックログへ引き継いだ。実験作成・学習・提出は行っていない。

## 先行研究

[Brasó・Leal-Taixé, CVPR 2020](https://openaccess.thecvf.com/content_CVPR_2020/html/Braso_Learning_a_Neural_Solver_for_Multiple_Object_Tracking_CVPR_2020_paper.html)はグラフ上のメッセージ交換で物体間の対応選択を学ぶ例。[補足資料](https://openaccess.thecvf.com/content_CVPR_2020/supplemental/Braso_Learning_a_Neural_CVPR_2020_supplemental.pdf)に制約を満たす丸めも記載される。辺ごとの閾値化だけで合法性を保証したとは扱わない。

[Schulterら, CVPR 2017](https://arxiv.org/abs/1706.08482)はnetwork flowの最適化結果を考慮して対応費用を学習する。費用学習の参考になるが、論文の平滑化した線形計画法が細胞分裂を含む現行ILPへそのまま適用できるわけではない。

どちらもBiohubの疎い注釈・分裂での改善実証ではない。今回の案は保存済み実験と先行研究から作った検証仮説である。

## 調査記録

独立した3つのsubagentにグラフ表現、情報の使い方、候補と不確実性を検討させ、主担当が検証・計算条件を整理。その後1つのagentを批判役へ切り替え、未知負例、修復上限、実予測教師、後段への伝達、solver費用を点検した。独立した科学的な再現検証ではない。

JSONのschema検査は12案・7分類・5選択の構造を確認する。改善効果を検証する検査ではない。
