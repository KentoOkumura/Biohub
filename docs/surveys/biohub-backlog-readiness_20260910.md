# Biohub 64候補の未決事項調査とユーザー判断

## 結論

仕様、既存実装、取得条件、参照版は調査で確定できる。予測誤差、最適な窓長、実際の改善幅は実データで測る事項であり、ユーザーに値を考えてもらう事項ではない。ユーザー判断は以下のD1〜D6へ整理した。Dはこのレポート内の質問番号であり、手法の名称ではない。

調査で特に変わった点は、未知候補へのsoftmax経由の勾配、公開proxyと公式分裂評価の局所構造の差、各epochの重みが保存されていないこと、損失の個数正規化が既存実装にあること、3D対応外部重みの区別とFOCUSの取得条件である。

次の比較は、公式全評価器の照合と胚を分ける基準予測の準備、その予測の誤差・回収上限分析を先に置くことを推奨する。精度実験の第一候補は、未注釈の子に対する接続損失の変更。予測する対象を大きく変える案では、母と二娘の組を直接採点するdivision_tripletsを推奨する。いずれも効果は未実測で、実験化は未承認。

## ユーザーに決めてもらう事項

| 番号 | 決めること | 選択肢と推奨 | 判断が必要になる範囲 |
| --- | --- | --- | --- |
| D1 | 次に実験化する候補と、最初の比較内容 | 推奨は「公式評価の残る照合 → 胚を分けた基準予測 → group_error_readout・oracle_stage_limits → partial_edge_mask」。大きく構造を変える案はdivision_triplets。全64件の具体的な最初の比較案を後半と各backlogへ記載した。選んだ案をその内容で進めるか、別の比較へ変えるかを判断する。64件すべてを実行する承認は求めない。 | 次の実験。後続候補は選んだときだけ判断する。 |

| D4 | 新しい候補で利用する学習済み重み・外部教師の範囲 | 自前学習のみ／主催者の公開重みを別比較に使う／FOCUSやTrackastra等も教師として使う。推奨は現行のrandom initialization再現を維持し、外部重みは選んだ追加候補に限定する。軌跡教師の最初の案は3D対応が明示されたTrackastra ctc。外部重みの評価胚への学習来歴が不明なら、完全に独立した評価とは呼ばない。 | 外部教師・新しい初期化を選ぶ場合。ユーザーが特定の外部モデル利用を明示した場合は、その承認を再度求めない。 |
| D5 | 人手で注釈・教師修正を行うか、工数をどれだけ使うか | なし／小領域の完全注釈／外部教師の誤り修正。実施するなら合計時間・担当者・中心だけか領域や接続までかを選ぶ。推奨はまず自動診断を優先し、人手なしでは成立しない候補を保留する。作業単価や件数は小規模な所要時間測定後に見積もる。 | dense_region_labels、teacher_review_labels、および完全な実画像教師が必要になった候補。人工例の作成に人手注釈は不要。 |
| D6 | FOCUSを取得する際の連絡先共有への同意 | Hugging Face上でモデル提供者への連絡先共有への同意が要求される。FOCUSを選ぶ場合のみ、条件をユーザーが確認して同意するか、利用を見送るかを決める。既に利用権がある場合は再同意不要。 | FOCUSの重み取得時のみ。一般的な外部モデル利用の確認と区別する。 |

D1には候補ごとの重要な設計選択を含めた。例えばpartial_edge_maskは、まず未知の子の損失項だけを外し、未知の親をsoftmaxの分母から外す変更は別比較とする案である。subvoxel_offsetは3軸の残差回帰、division_tripletsは母と二娘を組にした学習、motion_referenceは全体平行移動から始める案である。これらは調査で最良と確定した方法ではなく、対照と変更点が分かる提案である。

窓長、近傍数、雑音の分布、信頼度閾値、教師損失の重み、cache容量をユーザーに一つずつ指定してもらう必要はない。選んだ比較と予算内で、学習側の小規模測定・有限比較から設定する。新しく結果を左右する別方式が必要になった場合は、測定結果を添えて確認する。実験の完了・採用・不採用や実submissionは、既存の[AGENTS.md](../../AGENTS.md)に従い、その時点の証拠とユーザー判断を要する。今回改めて方針自体を問い直すものではない。

### 疎い注釈と接続・検出の損失

[現行学習ソース](../../experiments/exp002_unet3d_expandable_segments/official_source/scripts/train_unet_transformer.py)のcompute_lossでは、正例のある親行または子列を対象にする。片方の娘だけが注釈された親行では、他の子への辺も負例になる。ゼロlogitの人工2×2例で、未注釈娘へのlogitの勾配は約+0.099429だった。既知の子列だけを対象にすると、この例の勾配は0になった。

別の3親×1子の例では、未知の親のBCE（二値交差エントロピー）項を除外しても、その親をsoftmaxの分母へ残すと勾配は約+0.131176となった。分母からも外す算術例では0になった。正の勾配は勾配降下でそのlogitを下げる向きである。ただし分母の候補を減らせばよいと確定したわけではない。既知親しか残さない条件では学習信号を失い得る。負例の識別と候補対応を含めて比較する必要がある。

これはNumPyによる同じ損失算術と中央差分であり、Torch autogradや実学習の検証ではない。入力、勾配、抽出コードのSHAは[synthetic_checks.json](../../studies/biohub_backlog_readiness_20260910/synthetic_checks.json)へ保存した。

検出の正例・負例は既にサンプルごとに個数正規化され、接続もpairごとに平均される。したがってsample_loss_balanceに「個数正規化を足す」変更を重ねる根拠はない。残る比較案は、有効窓数の多い動画の寄与を等しくすること。get_window_dataは窓内に注釈ゼロのframeが一つでもあれば窓全体を除外するので、動画ごとの有効窓数を先に測る。

親候補softmaxは既に子ごとの親競合を表す。known_parent_constraintにはこれを超える追加目的がないためP4へ下げた。根拠が見つかるまで独立実験を作らないという整理であり、上位仮説の棄却や実験の不採用ではない。

### 公開proxyの分裂評価

DCTTA公開Notebookから保存したcompute_division_confusionは、親側と娘側が同じ弱連結成分にあり、その成分に分岐があれば正解と数える。公式コードは分岐に対する親・娘の局所対応と、異なる娘枝への対応を確認する。

抽出した関数の人工例で、正しい局所分岐は両方で許容された。一方、親の対応から2辺離れた分岐と遠い娘の子孫を同じ成分に入れた例では、公開proxyはTP=1、公式の当該局所構造チェックはfalseとなった。これだけでproxyを公式評価の代わりにはできないことが分かる。

別の人工例は指定した分岐に対する娘枝の区別を検査する。グラフ内の他の分岐が公式条件を満たす可能性があるため、その例を「公式の全分裂スコアが0」とは解釈しない。1つの予測分岐と2つのGT分裂の対応数は最大1となることも、公式の対応補助関数で確認した。

完全な公式評価器のnode対応・false positive・集計を含む照合と、実予測の順位変化は未検証。ローカルにはTorch・polars・tracksdataがなく、今回の検証は依存の小さい抽出関数までとした。これはユーザーに評価方法を選んでもらう未決事項ではなく、残る評価実装と実行の作業である。[人工例と検証範囲](../../studies/biohub_backlog_readiness_20260910/synthetic_checks.json)、[元の公開Notebook調査](biohub-public-baselines_20260910.md)。

### 候補対応、座標、計算の再利用

- 現行学習の最近傍のみの一意割当では、既に使われたGTが最近傍だった候補について第2近傍を探さない。小例では1対応に対し、許容距離内の最大対応数は2だった。実候補での頻度は未測定。これは同じ点群での人工比較で、公式の全node matchingそのものを再実装した比較ではない。
- 学習の検出閾値はraw logit 0.3でsigmoid換算約0.5744。現行推論configはsigmoid 0.99。閾値の表す値が異なる。一方、極大抑制の指定5µmと3µmは、現在の1.625µm格子ではどちらも3×3×3へ丸められる。「5と3で検出源が多様になる」とは言えない。
- 特徴抽出は整数座標を使い、特徴値には勾配が流れるが座標には流れない。連続位置補正を接続特徴に反映するなら補間が必要。最初の案として三線形補間を記載した。
- 時間attentionの出力は全入力窓に依存する。画像・重み・前処理・時間窓・切り出し・変形・padding・数値精度をcacheの識別に含める必要がある。frame IDだけのcacheは等価ではない。
- 64×64×64×32chのfloat16特徴は1frame16MiB。199動画・99個の2frame窓を全て別保存すると約615.7GiB。これは計算上の容量であり実ファイル測定ではない。変形、I/O、metadataの費用は別。動画・窓単位で必要分だけ再利用する案に絞った。[検証と計算条件](../../studies/biohub_backlog_readiness_20260910/synthetic_checks.json)。

### 現在の実行証拠と利用枠

[exp002のmetrics](../../experiments/exp002_unet3d_expandable_segments/metrics.json)ではCV・Public LBとも未取得。今回のKaggle status読み取りでもRUNNINGだった。ローカルの学習済みpthと独立胚予測は確認できなかった。現行のsample holdoutは胚を混ぜる診断であり、後から独立胚評価と読み替えられない。

train_unet_transformer.pyはaccuracy×recallの最大値に応じてedge_predictor_best.pthを上書きする。毎epochの重みは保存しない。graph_checkpointを比較するには次の学習でepoch別保存または各epoch時点のgraph評価が必要で、今の実行から過去の重みを取り出せるとは仮定できない。

Kaggle CLIのquota確認結果はGPU使用3.55h・残26.45h・合計30h、APIの更新時刻表記は2026-09-12T00:00:00だった。時刻文字列にタイムゾーンがないためJSTへ推測変換していない。進行中runの未反映消費や他用途の利用があり得るため、これは追加予算の確定値ではない。[確認値の記録](../../studies/biohub_backlog_readiness_20260910/service_observations.json)。

exp002のfull training所要時間の既存予測は約10.10hだが、これはsmokeからの外挿。2方向の追加学習・教師推論・最終推論の費用をそのまま表すものではない。[SESSION_NOTES](../../experiments/exp002_unet3d_expandable_segments/SESSION_NOTES.md)。

## 調査後も実行して確認する事項

1. 学習から除いた胚の予測、同じ候補集合・graph、重みと各生成物のSHA。
2. 誤差を暗さ・密度・境界・分裂に分けた集計、候補の一対一対応と段階別の回収上限。
3. 学習側画像からの位置誤差、欠測長、ぼけ、雑音、密度の分布。既知注釈だけから測れる範囲も明示する。
4. 外部教師の実画像での品質、取得後の来歴、重み・コード・依存のオフライン再現性。
5. 完全な公式評価器での人工例と実graphの採点。今回の局所関数検査だけで完了とはしない。
6. 学習、候補生成、特徴の再利用、推論全体の最悪入力でのメモリと時間。

以上は測定・実装・資料取得の作業であり、ユーザーに結果を決めてもらう項目ではない。実画像の解析は、生データの既存運用方針に沿ってKaggle上の次の承認範囲で行う。64候補の全学習を先に実施する依頼とは解釈していない。

## 全64候補の調査結果と最初の比較案

以下の比較案は提案であり、実験化や方式選択の承認ではない。D1は選ぶ候補と比較内容、D2は費用、D3は改善判定の共通判断。条件付き判断だけを末尾に示す。候補固有の詳細はbacklogを正とする。

### I01 / HYP-20260910-01

<a id="sparse_det_mask"></a>

**[sparse_det_mask](../../backlog/sparse_det_mask.md)** — 検出の未知領域を負例から外す

- 確認結果: 完全注釈領域のmaskはなく、暗いvoxelを確実な背景とする根拠もない。現行損失はGT以外を弱い負例にする。
- 最初の比較案: まず完全注釈の小領域で、現行損失と未知領域を除外した損失を比較する。背景を用意できなければ学習は保留する。
- 測定・資料待ち: 確認できる背景の範囲と全前景への退化。
- 条件付きのユーザー判断: D5。

<a id="partial_edge_mask"></a>

**[partial_edge_mask](../../experiments/exp019_partial_edge_mask/)** — 未記録の第2娘を負例にしない

- 確認結果: OR条件のmaskは未記録娘を負例にする。人工例ではBCE項を消しても未知の親のsoftmax勾配が残る。
- 最初の比較案: 既知の子だけを監督する変更を最初の比較とする。候補とGTの一意対応を固定し、未知・重複親を分母に残す影響を別診断する。分母変更を同時投入しない。
- 測定・資料待ち: 実候補での重複対応・未知親の頻度、娘回収と誤接続への影響。
- 条件付きのユーザー判断: なし（共通判断のみ）。

<a id="sample_loss_balance"></a>

**[sample_loss_balance](../../backlog/sample_loss_balance.md)** — 注釈密度に応じた損失集約

- 確認結果: 検出の正負項は各サンプルで個数正規化済み。接続も各pairの平均後にbatch平均。注釈ゼロframeを含む窓は除外される。
- 最初の比較案: 単純な個数正規化の追加は行わず、有効窓数に比例した動画の寄与を動画ごとに等しくする比較を提案する。元案の対象をこの差に限定する。
- 測定・資料待ち: 動画ごとの有効窓数と勾配寄与。実際に偏りがなければ追加比較は不要。
- 条件付きのユーザー判断: なし（共通判断のみ）。

<a id="dense_region_labels"></a>

**[dense_region_labels](../../backlog/dense_region_labels.md)** — 少数の完全注釈領域を追加する

- 確認結果: 既存GEFFは疎い中心・接続で、完全な領域注釈ではない。既知151分裂だけで全負例を定義できない。
- 最初の比較案: 暗さ・密度・境界で学習側の小領域を層別抽出し、中心・継続・分裂を漏れなく確認する。独立した再確認分を設ける。
- 測定・資料待ち: 単位領域あたりの所要時間、判定者間の一致、追加教師数。
- 条件付きのユーザー判断: D5。

### I02 / HYP-20260910-02

<a id="image_label_centers"></a>

**[image_label_centers](../../backlog/image_label_centers.md)** — 画像中心と注釈位置を分ける

- 確認結果: 注釈中心と画像由来の重心を同一と保証する資料はない。領域教師も現時点では未取得。

<a id="anisotropic_position"></a>

**[anisotropic_position](../../backlog/anisotropic_position.md)** — zとxyの位置不確実性を分ける

- 確認結果: 元画像はzとxyの間隔が異なるが、現行の間引き後の格子間隔は等しい。位置誤差の異方性は未実測。
- 最初の比較案: 既知中心への3軸対角Gaussian分布を出力し、固定分散との負の対数尤度比較を行う。分散の下限と校正は学習側だけで決める。
- 測定・資料待ち: 軸ごとの残差と校正、分散を大きくする退化。
- 条件付きのユーザー判断: なし（共通判断のみ）。

<a id="joint_position_edges"></a>

**[joint_position_edges](../../backlog/joint_position_edges.md)** — 中心位置と接続を同時に選ぶ

- 確認結果: 現行では中心を先に固定して接続する。公式対応は一対一なので同じ細胞の位置案を別細胞として数えられない。
- 最初の比較案: 1細胞につき排他的な複数位置案を作り、位置の画像支持と接続費用を一つの整数計画で選ぶ案。単独位置選択を対照にする。
- 測定・資料待ち: 同一細胞の位置案の対応、候補上限、整数計画の所要時間。
- 条件付きのユーザー判断: なし（共通判断のみ）。

<a id="match_radius_point"></a>

**[match_radius_point](../../backlog/match_radius_point.md)** — 7µm対応を意識して点を選ぶ

- 確認結果: 公式対応距離は7µm。これを広げて採点する変更は本候補ではない。
