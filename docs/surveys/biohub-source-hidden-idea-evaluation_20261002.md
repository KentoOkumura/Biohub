# Biohub 上位解法を伏せた発想評価

作成日: 2026-10-02

## 結論

**現行の運用とskillで一部の中核案は生成できたが、上位解法の具体的な処理を広く引き出せるという評価には届かなかった。** 公開前の入力から会話履歴なしの2コンテキストで生成し、上位15解法から選んだ16項目を採点した。中核処理まで具体化した一致は、初期案が両回2件、最終10案がAは2件・Bは1件、優先5案が両回1件だった。

当時の固定モデル方針で扱える9項目でも、最終案と優先5案の具体的一致は両回1件に留まった。したがって、今回の不足を画像モデルの学習制約だけでは説明できない。通常接続と母・2娘の分裂をまとめて選ぶ案は出たが、部分注釈の評価確率の分解、公式評価の個数変化を教師にするgraph修正、段階的な弱い検出回収、分裂修復後の再判定などは中核処理が不足または未生成だった。

前の回答で挙げた既存案と上位解法との類似は、具体化・実行まで到達できた証拠として扱うべきではない。今回の結果が支持するのは一部の発想を生成できた範囲であり、全部を独力で思いつけたという判断や、その能力がないという断定ではない。

## 調査目的

上位解法の解説を渡さず、公開前の情報だけから、現行の運用と`kaggle-idea-forge`がどこまで具体的な改善案を作れるかを評価する。既存の案と解法の類似を後から探す作業とは区別する。採点対象は手法の具体性であり、提出スコアや実験の採否ではない。

## 対象と証拠範囲

- 対応する上位仮説: なし
- 対象実験: 新しいKaggle実験は作成していない。公開前の`exp003`、`exp029`、`exp041`、`exp043`、`exp045`、`exp047`、`exp048`、`exp049`の構造化された記録を入力にした。
- 入力: 2026-09-27 17:41:06 JSTのGit commit `7b648a3`から、コンペ・指標・データ仕様、当時の学習方針、exp043の基準構成契約、実験の数値を抽出した。現在の候補一覧、過去の発想レポート、上位解法、後日の実験結果、Privateスコアを生成担当へ渡していない。
- 実データ・重み・新しい予測は使っていない。入力のSHA-256、抽出方法、元記録は[入力manifest](../../studies/biohub_source_hidden_eval_20261002/input_manifest.json)と[準備script](../../studies/biohub_source_hidden_eval_20261002/prepare_evaluation.py)に保存した。
- 評価方法: 会話履歴を引き継がない新しいコンテキストで、同じ入力と現行skillを使う2回の生成を行う。A・Bは今回の生成回の識別子。モデルの指定を変更していない。生成とは別のコンテキストで原文と採点基準を照合し、その後に固定済みの出力を採点する。
- 判断できないこと: 当時のモデルやskillの能力、上位解法全体の再現可能性、実装後の精度、skillを使わない場合との差、発想の成功確率。

## 生成と採点の手順

1. コンペ・指標・データ仕様、当時の学習方針、現行skillを読み、最初の6案を保存する。この段階では基準構成の契約・実験の数値履歴を読ませない。
2. 次に基準構成と時点固定した実験の数値を読み、skillの表現・情報・候補・検証の検討を順に行う。類似案をまとめ、具体的な入力、教師、損失、出力、選択方法、反証条件を持つ最終10案と優先5案を保存する。
3. 生成担当には採点基準、期待する案、他の生成回を渡さない。完成後の内容変更を防ぐため、初期案・最終案のハッシュを記録する。
4. 上位15解法の原文から選んだ16の仕組みを、初期6案、最終候補全体、優先5案の3段階で別々に採点する。16件は網羅的でも、Privateスコアへの寄与で重み付けした集合でもない。互いに一部重なる仕組みもある。

各項目は、該当なし・名称だけを0、似た方向だが中核処理が不足する案を1、入力・教師または目的・出力・選択方法を反証可能な比較へつなげた案を2とする。2は実装・精度の検証済みという意味ではない。仕組みが数値履歴から再利用されたものか、履歴を読む前に出たものかも区別する。

当時の固定画像モデル・固定trackerの方針で扱える項目が9件、画像モデル等の学習方針変更を必要とする項目が7件。優先5案は当時の方針に従う。条件付きの方針変更案は全候補の発想として採点し、無断実行の承認にはしない。現行skillの構造検査は記録形式の確認であり、科学的妥当性の採点とは別に行う。

両生成回とも初期案と独立検討の記録を保存した後の具体化が長引いたため、親が進行中のturnを中断し、同じコンテキストを再開して検討済みの内容を短い10案へ確定するよう指示した。10案はskillが認める10〜14案の範囲内で、採点対象や期待解は伝えていない。各回自身の保存済みメモ以外に許可入力を増やしていない。[介入記録](../../studies/biohub_source_hidden_eval_20261002/finalization_intervention.json)を保持し、無介入の自律生成とは区別する。

採点基準の初版は生成担当を起動する前に作成した。独立した原文照合で7項目の記述を訂正し、生成出力を見る前に訂正版を固定した。特に17位の教師は公式combined score差そのものではなく、公式評価で数える正解・誤りの変化と個数項から作る近似的な効用である。初版、[訂正記録](../../studies/biohub_source_hidden_eval_20261002/rubric_errata.json)、[訂正版](../../studies/biohub_source_hidden_eval_20261002/effective_rubric.json)、[原文照合](../../studies/biohub_source_hidden_eval_20261002/judge/rubric_source_audit.json)を保持した。

## 解釈

失敗証拠を別用途へ移す発想、候補回収と実際の選択の区別、教師未知の扱い、実行前の診断条件は両回に現れた。上流の微調整から離れた案を作る目的には沿っている。特に通常接続と分裂の共同選択は、基準構成の詳細・数値履歴を読む前から具体的だった。

一方、関連する方向性から、入力・教師・費用・処理順を上位解法と同程度の具体性へ落とす部分が弱かった。既知graphへ戻す教師と公式評価の個数変化による教師、未知注釈のmaskと評価確率の推定、1回の校正と暫定graphからの反復選択は、意味の違う処理である。名称の近さで同じ案に数えると、発想能力を過大評価する。

当時の方針が新しい画像学習の実行を制限したことは確かで、初期に出た画像対応案も優先5案から外れた。ただし、方針内9項目の具体的一致も1件だったため、広い不足をこの制約だけに帰すことはできない。skillが定める5枠に沿った選択は両回で似ており、記録形式の多様性が上位解法の処理の多様性を保証していない。

数値履歴を読んだ後の最終案で、具体的一致の種類は増えなかった。Bでは画像対応案が最終カードから落ちた。これは今回の入力・時間・確定指示を含む運用下の観測であり、履歴を読むこと自体の効果や、他の生成回でも同じ結果になることを示す比較実験ではない。

## 評価の限界

- ファイルを伏せる指示と会話履歴なしのコンテキストを用いたが、共有filesystem上での指示による分離であり、OSでアクセスを遮断していない。両回のアクセス記録に禁止資料の閲覧は報告されていない。モデルの事前学習に含まれる知識は除外できない。
- 親は上位解法を知った状態で時点と実験記録を選んだ。抽出はGitの保存内容から行い、基準は出力の閲覧前に固定したが、資料選択の偏りは残る。
- 現在のskillとモデルを、過去時点の入力に適用した評価である。当時のskill・モデル・利用可能な時間を再現した評価ではない。skillを使わない対照も設けていない。
- 初期6案も当時の学習方針を読んでいる。その本文には既存の実験名や、娘ごとに母を予測する教師の定義などが含まれる。基準構成の詳細・数値履歴を読む前の生成ではあるが、過去の手法に関する情報が全くない状態ではない。
- 2回の生成と、同じモデル系列の別コンテキストによる採点である。発見確率やskillの因果的な効果は推定できない。原文との照合は行ったが、上位解法のコード・重みを再実行していない。
- 採点項目は選ばれた16の仕組みであり、15解法全部を網羅していない。項目は一部重なり、重要度も同じとは限らない。件数を勝者との能力差やスコア比へ換算できない。
- 生成案は実装・訓練・公式評価を行っていない。完全一致の判定は中核処理を具体的に記述できた範囲に限る。教師の件数、cacheの取得可否、正解注釈を使わない候補選択、12時間以内の実行は未確認である。
- 親が中断・再開して短い最終案への確定を促した。期待する手法は教えていないが、最後まで無介入で実行できた証拠にはならない。
