## 手法契約

- input: 固定trackerの融合後softmax確率、元検出ID・補正座標、ILP後graph、運動参照。
- target / objective: 得点の参照範囲だけを変えたときの親割当と全graph公式評価の差を測る。
- output: 同じ初期node・対照由来の再追加node上の再接続edgeと監査記録。
- loss: なし。モデルを再学習しない。
- decode / context unit: 隣接2-frameの候補に現行motion割当を適用し、動画全体の後処理へ渡す。
- 実装区分: 特定論文・Notebookの再現ではない独立案。リポジトリ内の変更classは postprocess。
- 判断できる主張: 保存済み未選択辺の得点を渡すこと単独の効果。検出回収や分裂構造の同時選択の効果は判断できない。

## 実装方法

- 元score cacheは融合後確率`p > 1.0e-8`を保存したものを使う。`p > 0.10`に縮小したexp047 cacheを代用しない。exp043選択辺の得点を保持し、元cacheと重複する辺は確率一致を検査する。元ILP nodeではない再追加nodeにcache得点を結び付けない。
- 対照は元ILP graphを現行後処理へ渡す。変更側は同じILP graphと対照由来の再追加nodeを使い、再接続の得点辞書だけにILP未選択の保存得点を追加する。幾何gate、運動推定、割当、費用係数、後続処理を固定する。
- 内部診断は各胚11～20位。cache・元ID・元ILP graph・対照最終graphの一致と、両胚で得点が費用に入り割当が変わることを進行条件とする。最終評価は各胚21～30位。どちらも`SHA256(42:動画名)`順位とhead manifestで固定する。
- 学習variant 0、評価arm 2、fold 0、booster 0。control再学習なし。GPUは使用しない。各胚21位の新規動画を1本ずつCPUで先行実行し、正解ラベルを参照せず得点cache取得の時間・容量・メモリを測る。1動画の推論上限は1800秒。各動画の実測時間に評価対象20動画と安全係数1.5を掛けた予測時間が1本でも10時間以上なら拡大を止める。これらの値は`config.yaml`の`runtime.cpu_pilot`と`data.evaluation_videos`を正とする。CPU試行の結果を確認してから内部診断と新規20動画の全評価へ進み、GPUへの切替は行わない。
- 受け入れ条件: `make validate-exp`、`make check-exp`、`make test-exp`、Jupytext整合、元graph一致、欠損理由・再追加IDの監査、内部進行条件、条件成立時のKaggle全graph公式評価、動画・胚別の数値とSHA・kernel versionの記録。条件未達なら全graphを実行せず公式score未計測と記録する。
- 不確定なcache件数・割当変更件数・score・費用・SHAは実行時確認事項で、設計の未決事項ではない。採否・完了とsubmissionはユーザーの判断を待つ。

## 最小の反証可能な検証

- 検証方法: まずexp043と同じ固定入力・重み・融合得点・`p > 0.48` のILP候補・ILP解を再現する。ILP後の元node/edgeを両条件に複製し、対照の初回再接続から決まる再追加nodeを両条件で固定する。再追加がある動画では同じnode集合上で2回目の再接続を各得点辞書で実行する。再追加がない動画では初回再接続を比較する。幾何規則・費用係数・後続処理は同じとし、後続で生じたnode差は成果に含めて段階別に記録する。
- 得点と欠損の契約: 元cacheの `coords`、`edge_src`、`edge_tgt`、`edge_prob`、`admitted` と元ILP graphのID・座標・得点を照合する。新規取得cacheには各隣接時刻で実際に採点した元検出IDの範囲を保存する。組ごとに「ILP選択済み」「未選択だが保存済み」「採点済みで保存閾値以下」「採点対象外」「再追加nodeを含む」「明示的な0点」を分ける。旧cacheで保存閾値以下と未計算を区別できない場合は「理由未判別」として数え、全pair採点済みと称しない。再追加nodeはID数値が元候補に重なっても未採点として扱う。両条件で欠損は0点のままにし、得点を持つ未選択辺だけが費用差となる。
- 内部診断: `SHA256(42:動画名)` で各胚11～20位の計20動画を使う。これはexp045・exp047・exp049で詳細分析済みの集合なので設定選択や未使用評価に使わない。各胚11位の2動画でcacheとILP graphのID・座標・選択辺を照合し、対照の再接続後・最終graphを保存済みexp047対照と照合する。その後20動画で得点が新たに渡る再接続候補数、両条件の割当差、既知親の回収・破壊、判定できる誤親、分裂数と後段での残存を記録する。疎なGEFFの未知辺は誤りと断定しない。
- 全graph進行条件: 対照再生のID・ILP辺・最終graphが一致し、両胚で新たな得点が実際の再接続費用に入り、各胚で少なくとも1本の割当が変わり、再追加nodeと得点欠損の分類が監査可能であること。いずれか未達、または1動画の実測からNotebook12時間・週45GPU時間の上限を超える見込みなら新規20動画へ進まない。内部診断の正解を見て係数・閾値を調整しない。
- 最終評価: 上記条件を満たした場合、同じハッシュ順位の各胚21～30位、計20動画を事前固定してKaggleで固定tracker得点を新規取得する。head学習の各胚1～10位と詳細分析済み11～20位を除外し、選択表とhead manifestを照合する。両条件を同じ元得点・ILP解・再追加nodeで実行し、動画・胚別の全graphを同じ公式評価器で採点する。各胚を入れ替えた追加設定選択や外側結果からの閾値探索は行わない。公開画像モデルのtrain学習来歴により独立CVとは呼ばず、固定公開モデル下の条件付き評価とする。
- variant / config / fold / booster数: 学習0、ILP選択辺のみの対照1と保存済み未選択辺も渡す変更1、fold 0、booster 0。費用係数、幾何gate、得点保存閾値は比較結果から調整しない。
- control再学習: なし。trackerと座標headの重み、得点の生成条件を固定する。
- 想定runtime / resource: 元cacheが使える内部診断はCPU中心。新規20動画の得点取得にはKaggle GPUが必要で、対照と変更側の後処理・公式評価は可能ならCPU Notebookで実行する。1動画の得点取得・cache容量・後処理時間・peak RSSを実測してから全件費用を計算する。Kaggleのみ・課金なし・週45 GPU時間以内・Notebook1回12時間以内を守る。

## 成功条件と停止条件

- primary指標: 同条件対照との差として各胚の全graph公式combined score、adjusted edge Jaccard、division Jaccard。両胚を合算した数値だけでは判断しない。
- 成功条件: 新規評価20動画で各胚の公式combined scoreが対照を上回り、division Jaccardがどちらの胚でも悪化しない。得点の受け渡しによる変更辺が後段まで残ったことを確認する。
- 必須guard: 元cacheの得点保存閾値と採点範囲、得点ありに変わる候補率、再追加nodeの欠損率、親順位と変更辺、既知正解の回収・破壊、判定できる誤親、公式edge FP・分裂件数、後処理後の残存、動画別の最悪悪化を記録する。保存済み得点への変更だけで分裂改善を保証しない。
- 成功時の次段階: 採否・完了・実際のcompetition submissionは別途ユーザー判断とする。最終評価だけでPublic LBの改善を主張しない。
- 失敗時の停止範囲: cache・ID・対照graphの照合不能、内部診断で費用へ得点が届かないか割当が変わらない、予算超過見込み、または最終評価で両胚の成功条件未達なら、本案の拡大と採用を止める。公式score未計測の場合はその旨を記録する。不足得点の取得方法や再接続の費用・競合処理の変更は別候補として再設計する。

## 実行しないこと

- 禁止する代替実装、proxy、同一OOF上の救済探索: tracker/ILP費用の再学習・調整、得点clipping、ILP候補範囲やnodeの同時拡張、得点欠損の負例化、外側評価での閾値探索。再追加nodeや低得点検出点を新たにtracker採点しない。exp047の`p > 0.10`縮小cacheを全得点cacheの代用にしない。
- 壁打ちで採らなかった案と理由: exp050は共有得点学習と集合ILP、exp051はILPでの得点上限・費用比較。本案はILP後の得点参照だけ。取得できない得点を距離proxyで代用すると問いが変わる。

## リスク

- leakage / validation: 画像モデルと座標headの学習来歴を含む条件付き比較で、独立CVとは呼ばない。既に分析した20動画を未使用評価へ戻さず、方式・閾値・checkpointの選択は学習側内部に限定する。未知注釈を負例化しない。
- hidden test: 全test動画の画像と固定予測だけを使い、GEFF・正解細胞数・公開testと同じ動画数を使わない。隣接時点edge、娘の親高々1・母の娘高々2。未知入力/時間上限時は合法な元graphへ戻す。保存cacheが必要項目を欠けば取得費用を見積もり、勝手に代用しない。
- runtime / memory: CPU辞書参照中心だが、後処理再生に画像・座標補正が必要なら取得費用を計上する。保存候補量によるメモリと全動画時間を測る。
- 再現性: 入力動画・窓・候補ID・座標・得点と存在mask・重み・source・config・選択結果の版とSHAを保存する。
