### 入力・予測対象・出力・推論方法

- input: exp043の固定検出ID・補正座標と融合後の接続確率、exp047と同じ拡張候補。
- target / objective: 学習側内部の動画で、固定後処理後の公式combined scoreを最大化する。Optunaで出現・消失・分裂費用を選び、上限処理側だけ得点上限も選ぶ。
- output: ILPが選択した接続graphと、同じ後処理を通した最終予測。
- loss: なし。モデル重みの学習は行わない。

- 処理単位: 動画全体のgraph。学習側胚でパラメータを選び、他方胚の事前固定動画で評価する2方向。
- 実装区分: ユーザー提案の上限処理をそのまま比較する。外部参照手法の再現ではないため、このリポジトリ内の `faithful` / `staged-faithful` / `proxy` 分類は適用しない。

### 最小の反証可能な検証

- 検証方法: 同じ拡張候補で、A「元得点＋Optuna費用調整」とB「上限処理＋Optuna費用調整」を比較する。両条件の候補IDと元得点を照合し、小規模な動作・計算時間確認後に同じ実験内で探索と両胚の全graph公式評価まで行う。graphを作らない接続recallではこの復号変更の効果を判定できない。
- 費用探索: 出現0～1、消失0～3、分裂-1～2の連続一様分布を両条件に引き継ぐ。各方向・各条件の初回trialは既定費用 `(0, 2, 1.2)` とし、上限処理側の初回だけ `cap = 1` に固定する。残りのtrialでは上限処理側の `cap` を0.20～0.50の連続一様分布からOptunaで選ぶ。上限0.20で228本中158本、0.40で45本が同点になるexp049診断を範囲の根拠とし、改善の証拠とは扱わない。両条件とも方向ごとに最大12 trial・経過6時間、TPEのstartup 4 trial、seed `42 + fold`、有効trial 4件以上とする。固定初回も12件に含め、上限処理側の連続探索は最大11件。solver非最適・出力不正・公式評価失敗は失敗trialとして除外する。有効trialが4件未満ならその方向の比較を停止し、4件以上なら完了済みtrialから選ぶ。
- 分割と選択: `SHA256(42:動画名)` の胚ごとの昇順を固定する。各方向で学習側胚の31～35位の5動画を内部調整に使い、他方胚の21～30位の10動画を外側評価に使う。胚を入れ替えて2方向を行い、外側20動画は両条件で同一にする。動画名と選択SHAを予測・教師照合前に固定する。exp049の診断対象11～20位は着想に使った既視データである。exp050の外側21～30位もその結果を見た後は未使用評価と呼ばず、公開画像モデルの学習来歴を含む条件付き比較とする。外側では内部で凍結した各条件1構成だけを評価し、結果を見て再探索しない。
- trialの選択: 学習側5動画の固定後処理後の公式combined scoreを件数集約して最大化する。同値ならdivision Jaccard、なお同値なら出現・消失・分裂費用の辞書順、上限処理側でさらに同値なら大きい `cap` を選ぶ。外側の正解をtrial選択に使わない。
- ILPの同点: 両条件とも候補確定後は `(source_id, target_id)` 順でILPへ渡し、同じsolver版・設定・thread数で解く。元得点の二次目的や正解親の優先を加えない。同じ入力を再実行して最適目的値と選択辺の一致を小規模動作確認で検査し、不一致なら再現性を解決するまで全graph評価へ進まない。exp050対照と候補順序が異なる場合は、同じID順で対照を再実行する。
- variant / config / fold / booster数: 2条件×胚入替2方向。新規ニューラルネットワーク・boosterとも0。各方向・各条件のOptuna試行数と経過時間を別に記録する。
- 実行構成: 各方向と条件を1本ずつCPU Notebookに分け、合計4本の調整結果を同じ設定・分割・入力SHAで照合する。各Notebookは対象条件のtrialとpilotだけを実行する。4本すべてで有効trial 4件以上を確認した後だけ外側評価へ進む。
- control再学習: なし。費用調整対照の再探索は、入力・探索予算・分割が一致する保存済み対照を再利用できない場合に必要。
- 全graphへ進む条件: 上限処理なしの出力が同条件で再現され、候補集合・元得点・後処理が不変で、上限処理がILP費用だけに適用され、小規模ILPが最適解かつ妥当なgraphを返し、見積もりが計算上限内であること。外側の正解回収数で進行可否や上限を選ばない。
- 想定runtime / resource: 保存済み予測を使うKaggle CPU Notebookを優先する。対照を再利用できない場合の探索上限は2方向×2条件×6時間の計24時間で、方向と条件ごとの4 Notebookに分け、それぞれ12時間以内に収める。完了済み内部調整の動画別ILP上限1200秒は変更しない。再試行する外側評価は動画別3600秒とし、外側20動画×2条件を単一Notebookで実行する。メモリ使用率80%とNotebook 12時間を停止上限とする。必要な再抽出のみ既存の週45 GPU時間以内・課金なしの制約に含める。提出推論12時間以内を維持し、探索時間と推論時間を別に計測する。単一Notebookの外側評価が完走しても提出時の全動画推論が12時間以内とは断定しない。

### 成功条件と停止条件

- primary指標: 両胚それぞれの全graph・固定後処理後の公式combined score。
- 成功条件: 上限処理側が費用調整のみを両胚で上回り、両胚のdivision Jaccardが非悪化。採用候補とする際は同じ対象のexp043との比較も提示する。
- 必須guard: 既知接続の回収・喪失、注釈で判定可能な誤接続、分裂、親なし、同点となった候補数、solverの最適性と時間を胚別に記録する。部分注釈の未知辺を真の誤接続と断定しない。同点件数や上記228本の診断だけを改善判定に使わない。
- 外側評価の時間切れ時: SCIPのstatusがTIMELIMITで非空の暫定解を返した場合だけ、全ILP制約、0/1整数性、変数境界、目的値を元モデルに照らして検証し、通過したgraphを後処理と公式評価へ渡す。最適性は未証明として動画別にstatus・実測時間・検証値を記録する。暫定解がない、検証に失敗する、または他の非最適statusの場合は停止する。暫定解を使った公式scoreは最適ILP同士の純粋な比較として解釈しない。
- 成功時の次段階: 費用調整対照との差、exp043との差、両胚の各成分と費用を示してユーザーに採否を確認する。共有得点モデルへの上限処理の追加やsubmissionは別承認とする。
- 失敗時の停止範囲: 入力同一性が崩れる、不正graph・非最適解・計算予算超過が生じる場合は探索拡大を止める。評価で改善しなくても、同じ外側動画を見ながら上限範囲・費用・同点処理を選び直さない。

## 実装方法

- 元の `edge_prob` を候補生成と後処理に残し、ILP接続費用用の属性だけへ `min(edge_prob, cap)` を渡す。候補IDと元得点の配列は両条件で一致させ、ID順でILPへ登録する。
- exp050の5分割captureから固定x138 cacheを直接読み、動画一覧、選択SHA、各cacheのSHAを照合する。対象動画だけ作業領域へ複製し、GNN学習結果は参照しない。候補IDと元得点、solver版・設定、後処理版、対照graphのSHAを両条件で照合する。条件不一致なら同じ入力から費用調整対照も再探索する。
- 先に両条件の既定費用・`cap = 1` を小規模な動画で解き、最適終了、graph合法性、候補不変、元得点不変、後処理不変、同一入力の再実行一致を確認する。上限処理で生じる同点数とILP時間を測る。これは公式scoreの代用としない。
- Kaggle上で2方向・2条件の費用探索と、凍結設定による外側20動画の全graph公式評価を行う。各trialの費用、cap、選択指標、solver状態、時間、入力・出力SHAを保存し、胚別に既知辺の回収・喪失、判定可能な誤接続、分裂、親なしを記録する。
- この実験は重み学習をしない。active variantは得点上限なし・ありの2条件、胚入替2方向、新規model 0、booster 0、既存control再学習0とする。
