## 手法契約

- input: exp015の中央2時点の固定候補・画像特徴・位置特徴と、同じ動画の直前時点の固定候補の物理座標。予測済みの過去trackや正解対応を入力しない。
- target / objective: 中央の隣接2時点に対する既知のGEFF接続を学習する。5 µm以内の距離順一対一対応と教師maskをexp037/016から維持する。
- output: 中央の全source–target候補の接続logit。既存trackerのlogitへ、選択した過去候補から計算するdelta logitを加える。中央の接続候補は削除しない。
- loss: exp037と同じsource軸softmax後のfocal weighted binary cross-entropy。gamma 2、分裂weight 1、既知正例を持つsource行またはtarget列を含める既存maskを維持する。
- decode / 推論方法: 最初は隣接2-frameの確率・閾値0.5の指標のみ。後続の全graphでは既存の復号・修復を固定し、別途承認後に実装・実行する。
- 処理単位: 直前1時点を補助入力に持つ中央2-frame窓。学習・比較の対象窓はexp037と同じ18,707窓で、既存の空GT窓除外を維持する。
- 実装区分: 過去候補を制限する新設計であり、exp037の全候補版と等価とは扱わない。このリポジトリ内の管理用語では`staged-faithful`とし、新設計の学習・単体評価を先行し、全graph評価は後段へ分ける。

## 実装方法

1. 過去点をP、中央接続元をA、接続先をBとする。Aごとに直前時点の有効なPとの物理距離を計算し、近い順に最大8点を選ぶ。半径制限は加えない。同距離はcandidate ID昇順で決定する。無効点・paddingを除外し、8点未満なら全有効点を使う。
2. 選択はA単位で1回だけ行い、同じAから全Bへの接続候補で共有する。GT、接続確率、検出得点を選択に使わない。予測した1本の過去対応には固定しない。
3. 選択した点だけをgatherした後、各P–A–Bについてexp037と同じ13次元を作る。内容はA−P、B−A、両変位の差の3ベクトルとそれぞれの長さ、2変位のcosine。物理座標を使い、ベクトル・長さは5 µmで規格化、clippingなし、cosine epsilonは1e-8とする。
4. `Linear(13,32) → GELU → Linear(32,32) → GELU`と得点用`Linear(32,1)`を維持する。選択したPと「過去を使わない」選択肢の間でsoftmaxを取り、32次元を加重平均する。後者の特徴はゼロ、学習可能な得点の初期値は0。Bに応じてattentionの重みは変わる。
5. biasなし・ゼロ初期化の`Linear(32,1)`でdeltaを計算する。追加パラメータ数1,570は維持する。過去点がない場合はdeltaを厳密に0とする。先頭frameのみ履歴なしを許し、動画途中の必要cache欠損は停止する。

source・target方向のchunkは32、選択後の過去方向は最大8、gradient checkpointingは有効とする。K、tie規則、距離単位、全閾値・chunk・診断件数を新実験のconfigに保存する。全P–A–B特徴を生成してからmaskする実装は禁止する。距離計算はA×P、追加MLPはA×B×最大8に抑えるが、既存trackerの費用は残るため、候補数の削減率を速度改善率とは呼ばない。

### 1. 実装検証

- 同距離のID順、padding除外、8点未満、過去0点、動画境界、cache不一致、候補順序変更時の同一ID選択をテストする。
- 過去有効点が8以下の小例でexp037全点版と同じ出力・勾配になること、8超では同じ選択点に限定した参照実装と一致することを確かめる。
- delta重みを非ゼロにした小例でchunk・checkpointの有無による出力・勾配の一致と有限値を確認する。PyTorch依存テストをskipしただけでは受け入れない。
- 2-fold分割・教師mask・対象窓・中央の候補IDが保存済み対照と一致し、GTを変更しても過去候補選択が変わらないことを確認する。

### 2. 正しい前身候補を保持できるか

- 各foldの学習側の動画だけで、直前時点からAへ続く既知のGEFF接続を、同じ5 µm一対一対応で固定候補へ対応付ける。両端が候補へ対応した接続を分母、そのPがAの8近傍内にある接続を分子として条件付き保持率を計算する。
- 学習を進める条件は両foldそれぞれ保持率99%以上かつ分母が正であること。Kと条件は結果を見る前に固定し、失敗時にK・半径・方式を探索しない。外側評価GTを候補選択やfoldごとの調整に使わない。
- 全既知接続数、端点の検出不足、窓境界による対象外、分母・分子を併記する。密度、変位、分裂の有無ごとの件数と保持率も診断として保存する。密度はAから10 µm以内の過去候補数、区分は0–8/9–16/17以上、変位は0–5/5超–10/10超 µmとし、区分の境界を結果で変えない。
- 疎い注釈なので全細胞の保持率とは呼ばない。GT前身候補の挿入は禁止する。99%通過は計算削減の安全確認であり、精度改善の証拠ではない。

### 3. 計算費用を実測する

- metadataから全対象窓の有効候補数と選択後の三点組数を列挙する。各foldの学習窓を三点組数の四分位で4層に分け、seed 42で各層16窓を抽出する。16未満の層は全窓を使用し、選択リストを保存する。圧縮ファイルサイズは候補数の代理にしない。
- 2窓のwarm-up後、batch 2で実運用と同じ読み込み・選択・forward/backwardを測る。内部・外側評価用のattention推論とexp016対照推論は別に測る。評価側の件数分布はGTを見ずmetadataから求める。
- 外側を含む全対象窓から、中央pair数最大と選択後三点組数最大の窓を重複なく別抽出し、最大batch寸法でメモリと有限値を検査する。この負荷試験は代表窓の平均へ混ぜない。
- 4層の単純平均ではなく、各処理の実窓数で重み付けする。学習・毎epoch内部検証・選択後の外側評価・対照評価を別計上し、実測済み準備時間と保存費用を加え、未実行部分へ保守係数1.5を適用する。実行済みGPU時間を二重計上しない。checkpoint/予測の保存はbenchmarkの少量出力でも時間・サイズを測る。
- 12時間および実行前確認した週予算の残量を超える推定、peak allocated memoryが機器総量の80%超、非有限値・メモリ不足のいずれかで本学習を停止する。残予算不明も開始条件未成立とする。GPU割当数と実際の割当時間を記録する。
- benchmarkのoptimizer更新を本学習へ持ち込まず、公開重み・branch初期値・RNG・DataLoaderを再初期化する。学習中も経過時間から残所要時間を更新し、同じ上限を超える見込みなら記録・保存して停止する。

### 4. 両胚の接続比較

exp016と同じ外側窓で既知positive edge recall、教師mask内のfalse positive件数、既知分裂親の両娘回収件数・分母を保存する。部分注釈のため、教師上のfalse positiveを真の誤接続総数とは断定しない。学習内benchmarkの数値、内部checkpoint選択の数値、外側胚の数値を区別する。frame先頭・密度・過去保持失敗箇所別の結果は診断にとどめ、設定の救済探索に使わない。

## 成功条件と停止条件

- primary指標: 最終目的は公式adjusted edge Jaccardと0.1倍のdivision Jaccardの和。今回の初段は閾値0.5での両胚別positive edge recallを進行判断に使い、公式scoreの代用にはしない。
- 成功条件: 前述の保持率・費用条件を満たして学習が完走し、exp016保存済み対照より両胚それぞれpositive edge recallが厳密に改善する。
- 必須guard: 両胚それぞれ教師mask内false positive件数の増加が5%以内、既知分裂親の両娘回収件数が減らない。対照のfalse positiveが0なら新方式も0を要求する。評価分母が0の指標は自動合格させず判定不能として止める。公式score・Public LBは未計測と明記する。
- 成功時の次段階: 両胚の指標・実行証拠・残予算を提示し、ユーザーの承認を得て全動画graph推論とKaggle上の公式評価へ進む。submissionは別途明示承認が必要。
- 失敗時の停止範囲: 実装・保持率・費用の条件未達なら本学習を始めない。学習後の条件未達なら全graphを始めない。K増加、fold削減、epoch削減、別入力・別方式への置換を自動で行わない。実行状態とユーザーの採否判断を分ける。

## 再現性・リスク

- leakage / validation: 公開encoder・初期trackerの来歴にtrain動画が含まれるため条件付きの比較。候補保持率は各foldの学習側のみで進行判定し、outer側で救済調整しない。元の部分注釈maskの限界も引き継ぐ。
- hidden test: 過去候補は固定検出器だけから得る。frame先頭は過去なし、同動画・連続frameの照合を必須とする。train cacheの存在をhidden testで仮定しない。全graph推論の実装・費用は初段だけでは保証しない。
- runtime / memory: 候補選択の距離計算・cache読み込み・既存trackerの費用は残る。近傍8点化だけで12時間内と断定しない。密集・大移動では必要なPが落ちる可能性がある。
- 再現性: 入力・選択ID・split・source・config・モデル・予測のSHAを記録する。GPU演算の非決定性とdropoutを記録し、単純なchunk等価性テストを実行再現性全体の保証にしない。
