## 観測事実と根拠

- 実測済みの事実: [exp049結果](../experiments/exp049_x138_edge_selection_diagnostic/result.md)では、追加された既知接続547本のうち通常ILPで360本が落ち、そのうち228本では同じ娘に選ばれた別の親の得点が既知の正しい親より高かった。残りは、低得点の別親が選ばれた34本と親辺が選ばれなかった98本であり、本候補が360本すべてを解くとは仮定しない。
- 壁打ち時の追加集計: 上記228本について元得点だけを上限処理すると、正しい親と選択された別親が同点になる件数は下表となる。ILPの再実行や改善件数ではない。高い上限では正しい親まで同点にならず、低い上限では他の正しい順位も多く失う可能性がある。

| 得点上限 | 正しい親と選択された別親が同点になる件数 / 228本 |
| --- | --- |
| 0.5 | 0 |
| 0.4 | 45 |
| 0.3 | 97 |
| 0.2 | 158 |

- 集計手順: exp049の `artifacts/evidence/diagnostic_v6/competition_readout.json` の `new_edge_details` から `decision == "higher_score_parent_selected"` を抽出し、`score` と `selected_parent_for_daughter.score` の両方が上限以上の行を数える。2026-09-26に228行と上表を再確認した。
- 根拠ファイル / 一次資料: [exp049結果](../experiments/exp049_x138_edge_selection_diagnostic/result.md)、[競合診断コード](../experiments/exp049_x138_edge_selection_diagnostic/exp049_competition_readout.py)、[exp047要件](../experiments/exp047_x138_edge_candidates/requirements.md)、[exp043 config](../experiments/exp043_x138_self_trained_head/config.yaml)。
- 利用する保存済み生成物とSHA: 診断元の `competition_readout.json` のSHA256は `21a12a438121ca41fffd609aded04d3f7b1fceca3142688f1bd3e860dc8e03a0` で、[exp049 metrics](../experiments/exp049_x138_edge_selection_diagnostic/metrics.json)と一致する。実験に再利用する予測・重みは[exp043 metrics](../experiments/exp043_x138_self_trained_head/metrics.json)と[exp047 metrics](../experiments/exp047_x138_edge_candidates/metrics.json)を正とし、対象動画・候補ID・得点・SHAの一致を実行時に確認する。
- 仮定: Assumption: 誤った親への過大な得点差を除くと、他の接続得点、出現・消失・分裂費用と既存制約により正しいgraphを選べる事象がある。同点化だけで正しい親が優先されるとは仮定しない。

## この候補が直接検証する仮説と範囲

- 上位仮説のうちこの候補が検証する範囲: 固定した候補と構造制約の下で、得点の高い側の差を除くことが最終選択へ与える効果。
- この候補の具体的な仮説: 出現・消失・分裂費用を同じ条件で調整した上でも、接続得点の上限処理を加えると誤った親の選択を減らし、両胚の公式指標が改善する。
- 仮説が正しい場合に期待する観測: 新たに回収する既知接続が失う接続を上回り、判定可能な誤接続と分裂の成分を含め、費用調整のみより両胚の最終公式指標が改善する。
- 仮説を棄却する観測: 同点は増えるが正しい接続が回収されない、別の正しい順位を壊して最終指標が下がる、または費用調整のみを上回らない。
- この候補だけで上位仮説を判断できるか: いいえ
- 上位仮説の判断に残る検証: 母と2娘の共有得点の学習、対応なしの学習、制約自体の変更による効果。
- 既存候補との差: 共有得点学習は入力情報と損失から正しい順位を学ぶ。本候補は元得点を固定して高得点間の差を消す。[x138_local_graph_choice](x138_local_graph_choice.md)の複数graph生成・追加情報による選択も含めない。

## 入力・予測対象・出力・推論方法

- input: exp043の固定検出ID・補正座標と融合後の接続確率、exp047と同じ拡張候補。
- target / objective: 学習側内部の動画で、固定後処理後の公式combined scoreを最大化する。Optunaで出現・消失・分裂費用を選び、上限処理側だけ得点上限も選ぶ。
- output: ILPが選択した接続graphと、同じ後処理を通した最終予測。
- loss: なし。モデル重みの学習は行わない。
- decode / 推論方法: 元得点 `p` から候補を確定した後、ILPの接続費用だけを `-min(p, cap)` にする。上限処理なし側は `-p`。どちらも接続係数は-1に固定する。`cap = 1` は上限処理なしを含む。元得点を別に保持し、候補生成・順位による候補追加・後処理へ上限処理を波及させない。
- 処理単位: 動画全体のgraph。学習側胚でパラメータを選び、他方胚の事前固定動画で評価する2方向。
- 実装区分: ユーザー提案の上限処理をそのまま比較する。外部参照手法の再現ではないため、このリポジトリ内の `faithful` / `staged-faithful` / `proxy` 分類は適用しない。

- 再利用するコード / config / 生成物: exp043の入力・後処理、exp047の候補生成、exp049の接続選択診断。共有得点学習で導入したOptuna対照の探索・評価手順も、条件照合後に再利用する。

## 最小の反証可能な検証

- 検証方法: 同じ拡張候補で、A「元得点＋Optuna費用調整」とB「上限処理＋Optuna費用調整」を比較する。両条件の候補IDと元得点を照合し、小規模な動作・計算時間確認後に同じ実験内で探索と両胚の全graph公式評価まで行う。graphを作らない接続recallではこの復号変更の効果を判定できない。
- 費用探索: 共有得点学習の対照で定めた出現0～1、消失0～3、分裂-1～2の連続一様分布を両条件に引き継ぐ。既定費用 `(0, 2, 1.2)` と上限なしを含める。上限値の探索範囲・分布、追加次元を含めた両条件の共通探索予算は実験化前に確定する。
- 分割と選択: 探索と設定選択は学習側内部に限定し、外側では凍結した各条件1構成のみを評価する。exp049の診断20動画は着想に使った既視データであり、新しい評価とは呼ばない。先行実験の外側結果を確認して本候補を設計した場合も、その対象を未使用評価とは呼ばず、実験化前に評価動画を固定する。
- variant / config / fold / booster数: 2条件×胚入替2方向。新規ニューラルネットワーク・boosterとも0。各方向・各条件のOptuna試行数と経過時間を別に記録する。
- control再学習: なし。費用調整対照の再探索は、入力・探索予算・分割が一致する保存済み対照を再利用できない場合に必要。
- 全graphへ進む条件: 上限処理なしの出力が対照と一致し、候補集合・元得点・後処理が不変で、上限処理がILP費用だけに適用され、小規模ILPが最適解かつ妥当なgraphを返し、見積もりが計算上限内であること。外側の正解回収数で進行可否や上限を選ばない。
- 想定runtime / resource: 保存済み予測を使うKaggle CPU Notebookを優先する。必要な再抽出のみ既存の週45 GPU時間以内・課金なしの制約に含める。提出推論12時間以内を維持し、探索時間は別に計測する。上限処理は安価でも、同点の増加でILPが遅くなる可能性があるため小規模実測から上限を決める。

## 成功条件と停止条件

- primary指標: 両胚それぞれの全graph・固定後処理後の公式combined score。
- 成功条件: 上限処理側が費用調整のみを両胚で上回り、両胚のdivision Jaccardが非悪化。採用候補とする際は同じ対象のexp043との比較も提示する。
- 必須guard: 既知接続の回収・喪失、注釈で判定可能な誤接続、分裂、親なし、同点となった候補数、solverの最適性と時間を胚別に記録する。部分注釈の未知辺を真の誤接続と断定しない。同点件数や上記228本の診断だけを改善判定に使わない。
- 成功時の次段階: 費用調整対照との差、exp043との差、両胚の各成分と費用を示してユーザーに採否を確認する。共有得点モデルへの上限処理の追加やsubmissionは別承認とする。
- 失敗時の停止範囲: 入力同一性が崩れる、不正graph・非最適解・計算予算超過が生じる場合は探索拡大を止める。評価で改善しなくても、同じ外側動画を見ながら上限範囲・費用・同点処理を選び直さない。

## 実行しないこと

- 禁止する代替実装、proxy、同一評価上の救済探索: 候補生成前の上限処理、上限処理による候補追加・削除、後処理への変換伝播、既知の正しい親を優先する同点解消、元得点による高得点内の順位の復活、外側での上限・費用の調整。
- 壁打ちで採らなかった案と理由: 得点全体の一律縮小は順位を同点にする提案と異なる。費用を旧設定のまま上限だけ選ぶ比較は、接続の報酬と出現・消失・分裂費用の相対関係に依存するため主比較にしない。得点学習との同時変更は上限処理の追加効果を分けられないため本候補から除く。

## リスク

- leakage / validation: 固定公開重みとheadの学習来歴を含む条件付き比較であり、独立した交差検証ではない。診断対象228本は失敗例に限定した集計で、全候補での損得を代表しない。上限と費用は内部検証だけで選ぶ。
- hidden test: 推論時に注釈や正しい親を使わない。候補密度や得点分布が変わる場合の影響を、胚別・得点帯別に確認する。
- runtime / memory: 同点の増加はILPの探索量を増やし得る。対照と上限処理側の試行数・探索時間・有効試行数を併記する。
- 再現性: 元得点、変換後費用、上限、イベント費用、Optuna履歴、候補順序、solver版と設定、同点処理、入力・出力SHAを保存する。同点化自体は正しい親の優先を保証しない。
