- 仮説が正しい場合に期待する観測: 同じ候補予算で正しい局所graphが追加回収され、その利益が実際の選別と全動画の公式評価へ残る。

## 入力・予測対象・出力・推論方法

- input: exp043の固定候補ID・座標・画像特徴・得点、元graph、親交換・分裂・欠落経路・現状維持の全修復候補と境界制約。
- target / objective: 注釈で確認できる接続・分裂に整合し、娘の親重複などの矛盾がない局所graphを選ぶ。未注釈の違いだけを誤graph教師にしない。
- output: 各競合成分で共同選択した合法な修復操作と、その結果のgraph。最終出力は隣接時刻edgeとする。
- loss: 選択を学習する場合は部分注釈に整合する候補集合と確認済み矛盾を持つ候補を比較する。具体的な順位損失・集約・未知部分の扱いは未決事項。元と同じ目的関数だけで再選択して追加利益が生じるとは仮定しない。
- decode / 推論方法: 全修復候補と共有制約から成分を構成する。境界を跨ぐ候補や費用結合は成分統合または共有変数で扱う。娘の親最大1、母の娘最大2、点の重複使用禁止と時間順を守る。高得点だけを理由にedgeを固定せず、誤接続を解放できることを求める。具体solver・境界方式は未決。
- 処理単位: 親候補を共有する競合成分と短い時間窓。最大点数・解数・窓長は方式を先に確定し、学習側の費用測定で上限を決める。
- 実装区分: 複数の整合解を保持して選ぶ処理が中核。edgeの平均や閾値調整だけではこの案の実装としない。

本候補では通常点・回収候補それぞれの座標とIDを固定し、その採否・接続を比較する。元位置と補正位置の排他的な選択・整合した再採点は[joint_position_edges](joint_position_edges.md#x138の元位置と補正位置を使う比較の引き継ぎ)へ分離した。位置変更を本候補の初回条件へ含めない。

## 最小の反証可能な検証

- 検証方法: 同じ目的と候補の小例で分解前後の実行可能解の対応と最適目的値を照合し、同点解の辺差も記録する。時間打切りの解を最適値の一致の証拠にしない。次に同予算で逐次処理、等価な分解処理、分解で可能になった前後構造の同時選択を比較し、最後の方式の実選択と公式scoreを確認する。
- variant / config / fold / booster数: 逐次処理・等価分解・前後構造を含む同時選択の3条件を基本案とする。候補上限は別診断。位置状態は追加しない。学習する場合は2fold、booster数0。選択器・対照・総モデル数は未決。
- control再学習: 候補採点trackerは固定。選択器を学ぶ場合は同じ特徴・損失で単一解側の対照が必要かを契約に明記し、候補保持と学習量を混同しない。
- 想定runtime / resource: Kaggleのみ、週45 GPU時間以内・課金なし・1回12時間以内。複数解のsolver、再採点、後処理を含める。CPUで可能な候補選択をGPU時間と分けて計測する。

## 成功条件と停止条件

- primary指標: 候補内の正解局所graph回収と実選択、両胚の既知接続・分裂・判定可能な誤接続、最終公式combined score。
- 成功条件: 分解で合法解や既知両娘の実現可能性を失わず、同予算で可能になった構造選択が両胚の公式combined scoreを改善し、division Jaccardを損なわない。高速化だけでは成功としない。
- 必須guard: 現行graphだけの連結成分で独立性を仮定しない。境界競合・共有費用・高得点の誤edgeの解放、最大成分・時間・メモリを確認する。未知edgeを誤りと断定せず、正解参照の上限と実選択を分ける。
- 追加する診断: 同点の解が異なる場合も目的値・制約・境界費用を照合する。共同選択した通常辺・2娘・欠落経路が後段で保持・破壊される件数、公式対応後の接続と分裂の正解・誤検出・見逃し、元点の保持と追加点、node数調整を追う。候補生成、最大競合成分、solver、DeepCenter等の後処理、特徴取得を含む全工程を計測し、CPU時間とGPU割当時間を分ける。
- 成功時の次段階: 局所構造でしか測れない効果を含む進行条件と費用を満たしてから全動画へ進む。採否とsubmissionはユーザー判断。
- 失敗時の停止範囲: 分解で合法解が失われる、誤edgeを解放できない、境界矛盾、費用上限超過、または速度改善だけで最終精度が改善しない場合は拡大を止める。

## 実行しないこと

- 禁止する代替実装、proxy、同一OOF上の救済探索: 正解による候補補充、外側での解数調整、同一検出の複製、矛盾edgeの単純和集合、全修復候補を無視した分解、高得点edgeの無条件固定、同一目的の再実行だけを精度改善と呼ぶこと。
- 壁打ちで採らなかった案と理由: 全候補の一律平均は異なる構造を壊す。補正量の倍率調整は複数の整合解を保持する問いを検証しない。2時点先の直接対応を主に変える案は[x138_two_step_links](x138_two_step_links.md)で別に扱う。
