## 入力・予測対象・出力・推論方法

- input: 学習側の胚のZarr画像とGEFF注釈。外側の評価胚は推論時に画像と利用可能なmetadataだけを読み、GEFFは予測を固定した後の採点で使う。
- target / objective: exp002と同じ細胞中心検出と隣接時刻間の接続予測。新しい教師や損失は導入せず、比較用の基準予測を作る。
- output: 2個の選択済みcheckpoint、分割一覧、199動画の予測graph、動画別・胚別・全体の公式評価結果。併せて検出中心と検出得点、接続の閾値適用・最適化前の候補と得点、候補を有効とするmask、最終選択への対応を動画別に保存する。
- loss: exp002の重み付き検出損失と接続損失をそのまま使う。検出損失の重み1.0、検出負例の重み0.01を保つ。未注釈の子を扱う損失変更は後続の`partial_edge_mask`へ分ける。
- decode / 推論方法: exp002の検出時augmentationによる予測の集約、中心抽出、接続のsoftmax、整数線形計画によるgraph選択を維持する。検出閾値0.99、接続閾値0.5、推論batch size 4、最適化の各費用も参照configを固定する。
- 処理単位: 入力は2時刻の3D画像窓、推論と保存は1動画、外側の学習・評価の分割は1胚。動画間の座標共有や絶対時刻の共有は仮定しない。
- 実装区分: 参照モデルの教師・構造・推論を保ち、分割と記録を変更する。[用語集](../docs/glossary.md)に従うこのリポジトリ内の管理用ラベルは`faithful`。

## 親実験からの差分

- 変更するもの: 全199動画からのsample holdoutを、片方の胚で学習し他方を評価する2方向へ変更する。重み選択用の内部分割は外側の学習胚の中だけで作る。全対象の独立予測と中間候補の保存、固定公式処理による採点を加える。
- 固定するもの: exp002のsource、`TemporalUNet3D_SimpleNodeTransformer`、random initialization、seed 42、3 epochs、AdamW、learning rate 0.0001、学習batch size 16、workers 8、window size 2、downsample `(1,4,4)`、モデル幅、augmentation、損失、推論条件を維持する。内部の重み選択指標も`edge_accuracy_times_node_recall`を維持し、外側の公式指標でepochを選ばない。
- 再利用するコード / config / 生成物: exp002の学習・推論コードとoffline依存環境、exp003の固定公式評価器。CUDAの`PYTORCH_ALLOC_CONF=expandable_segments:True`をTorch import前に設定する。既存の学習済み重みは初期化にも使用しない。
- 新しく作るもの: 実験化後にtrain・inference・評価用Notebook、胚単位の分割manifest、動画別候補cache、予測manifestを作る。モデル・分割・評価器・設定の版とSHAを結び付ける。保存先は作成する実験の`artifacts/`配下とする。

## 最小の反証可能な検証

- 検証方法: 2方向とも同一構成で学習し、外側の評価胚の全動画を推論する。内部の分割は、学習胚の動画名をsort後に`random.Random(0)`でshuffleし、先頭の`max(1, 動画数 // 10)`件を重み選択用、残りを勾配更新用にする。これはexp002の分割処理を学習胚内へ限定したものとする。

| 外側の学習胚 | 勾配更新用動画数 | 内部の重み選択用動画数 | 外側の評価胚 | 外側の評価動画数 |
| --- | --- | --- | --- | --- |
| `44b6` | 64 | 7 | `6bba` | 128 |
| `6bba` | 116 | 12 | `44b6` | 71 |

- 分割の検査: 199動画の重複・欠落がないこと、各方向で外側の評価胚が勾配更新・重み選択のどちらにも含まれないことを確認する。smokeも各方向の勾配更新用動画から名前順で最初の1件を使う。内部の分割は学習中の診断であり、主評価とは呼ばない。
- variant / config / fold / booster数: 1構成、外側2fold、各3 epochs、選択済みモデル2個。foldは学習・評価の分割1組を指す。追加seedとboosterは0。内部で選んだcheckpointをそのまま使い、学習胚全件での追加refitは行わない。
- control再学習: 胚を分けるための新規学習2回を行う。exp002と同じ両胚混在splitの対照再学習は行わない。既存重みの再利用では評価胚の独立性を満たせないためである。
- 想定runtime / resource: KaggleのT4 2基、internet無効、無料枠内、1Notebook最大12時間。exp002の3 epochsは約7時間55分だったが、この分割での学習・199動画推論の合計は未実測。学習と推論を別Notebookに分け、小規模実測から両方向の残り時間を見積もる。実行前に残枠を確認し、後続の推論確認用の枠を差し引いた範囲で開始する。不足時は完成した生成物を保持し、枠の更新後に残りを再開する。
- 評価処理: exp003の`evaluate`、`per_sample_metrics`、`summarise`を含む公式処理を使用し、対応付け距離7 µm、物理scaleも同実験のconfigへ揃える。動画別の成分を保存し、胚ごとの集計に加え、199動画分の成分を公式`summarise`へ渡した全体値を記録する。単純な2胚の得点平均で公式全体値を置き換えない。

## 成功条件と停止条件

- primary指標: 胚を分けた交差検証（CV）の公式指標。胚別の公式指標・成分・有効件数と、全199動画の公式集計を記録する。今回は比較基準の作成なので、既存診断スコアを超える数値閾値は設けない。
- 成功条件: 全199動画について外側の評価胚を学習に含まない予測が各1件揃い、対象の欠落・未解決の実行失敗が0である。予測・中間候補・学習来歴の対応が追跡でき、同じ保存予測から公式成分と集計が再計算できる。指標が未定義となる動画は原因と有効件数を記録し、黙って集計対象から落とさない。
- 必須guard: 重み選択・閾値調整・教師作成に外側の評価胚の正解を使わない。部分注釈に含まれない検出を独自に誤検出扱いしない。2方向の評価前にモデル・推論・集計条件を固定する。各実行の予算と12時間制約を守る。
- 成功時の次段階: 生成物と公式評価結果を提示して、本実験の完了をユーザーに判断してもらう。後続は承認済みの順序に従い、[誤差分析](group_error_readout.md)と[段階別回収上限の確認](oracle_stage_limits.md)へ同じ基準予測を引き渡す。
- 失敗時の停止範囲: 胚の混入・予測の欠落・再採点の不一致・メモリ不足・時間制約超過があれば、影響する方向と、それに依存する分析の結論を止める。原因と保存済み生成物を記録し、両方向の成立までは基準予測全体の完成としない。別の仮説や候補全体を棄却しない。

## 実行しないこと

- 禁止する代替実装、proxy、同一OOF上の救済探索: 両胚で学習した既存重みの流用、動画ランダム分割を主評価の代用にすること、評価胚の正解を見てepoch・閾値・最適化費用を選び直すこと、公開Notebookの簡略評価器への置換は行わない。OOFは対象を学習から除いて作る予測を指し、その得点を見た後の設定探索はこの基準作成に混ぜない。
- 壁打ちで採らなかった案と理由: `group_error_readout`内で暗黙に学習する案は、生成と分析の実行費用・責務を明確にするため採らない。片方向だけの評価は両胚で比較する合意を満たさない。`partial_edge_mask`の同時導入は基準と損失変更の効果を分けられなくなるため採らない。外部重み、手動注釈、追加refit、モデル構造変更は今回の範囲に含めない。
- 対象外: hidden testへの提出とPublic LB取得。基準予測のCVと公開スコアを混同せず、後続の提出はその提出に対する明示承認に従う。

## リスク

- leakage / validation: 2胚しかなく、内部の重み選択は学習胚内の診断にとどまる。後続候補で同じ外側結果を繰り返し選択に使うと開発集合になるため、未知胚一般化の確証とはしない。画像前処理・内部の診断・smokeを含めて分割を検査する。
- hidden test: この候補の全件は学習データ内の199動画であり、非公開テスト全件の時間内完走を保証しない。推論コードは画像のみで実行し、注釈は採点処理へ分ける。
- runtime / memory: 199動画の候補cacheと推論は4動画の既存実行より大きい。動画ごとに保存して解放し、全特徴tensorの一括保持を避ける。時間や容量を理由に対象・epoch・解像度・batch sizeを無断で縮小しない。
- 再現性: seedだけでは同じ数値を保証しない。参照augmentationは各item内で新しいNumPy乱数生成器を作るため、exp002と同じ非決定性が残る。source・config・分割・checkpoint・候補・予測・評価器のSHAと実行環境を記録し、保存予測からの評価再現を検証する。
