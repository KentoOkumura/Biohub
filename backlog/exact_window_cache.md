## 入力・予測対象・出力・推論方法

- input: 固定公開モデル、元の全入力時間窓、前処理、crop、padding、変形、推論精度、抽出層・補間方法・候補座標。教師は別に主催者注釈を対応付ける。
- target / objective: 直接計算と保存済み特徴を使った下流計算の等価性を保ち、反復費用を減らす。
- output: 窓ごとの候補ID・物理座標・検出得点・候補点特徴と、重み・入力条件・対象一覧に対応するmanifest。基準得点や最終graphは別の比較用生成物として保存する。
- loss: なし。画像モデルと下流モデルの重みを固定して等価性を確認する。後続学習の教師は保存予測自体から作らず、主催者注釈を対応付ける。
- decode / 推論方法: 同じ下流モデル・同じ候補と復号へ直接抽出または保存特徴を渡す。予測得点だけの保存を、再学習に必要な特徴の保存の代用にしない。
- 処理単位: 1動画の元の時間窓と候補点集合。保存は動画・窓の区切りで行い、Kaggle Notebook間で読み出せる形にする。
- 実装区分: 等価な再利用を対象とする。時間窓の短縮、別精度への変換、特徴の選択・圧縮を加える場合は変化を明示し、無検証で同等と呼ばない。

## 親実験からの差分

- 変更するもの: 画像特徴を反復計算する処理を同条件の保存・読み込みに置き換えること。
- 固定するもの: 公開モデルの全重みと統計、候補生成、入力の全時間窓、前処理、精度、抽出箇所と候補座標、下流モデルと復号。
- 再利用するコード / config / 生成物: 選定公開モデルの基準推論、候補点への特徴取得、exp003で照合した公式評価器。
- 新しく作るもの: 窓・候補と特徴の対応、保存・再読み込み、条件の違うcacheを混用しない確認、費用と等価性の記録。

## 最小の反証可能な検証

- 検証方法: 小規模な同一窓で直接特徴と保存後の特徴を比較し、同じトラッカーの得点と最終graphも照合する。窓端・高密度の例を含め、必要な特徴の欠落、精度差、対応順序の誤りを調べる。実保存量と読み込みを測り、全対象への容量・費用見積もりが成立した場合に広げる。
- variant / config / fold / booster数: 同じ固定重み・対象一覧について直接抽出と保存特徴の2経路のみ。学習は行わず、来歴を含む評価条件も揃える。
- control再学習: なし。新しい検出器やトラッカーを学習しなくても比較できる。
- 想定runtime / resource: 初回抽出はGPUを使い、保存・読み込みの費用も計上する。下流計算や集計をCPUで行える範囲は実測して選ぶ。Kaggleのみ週30時間のGPU枠、セッション・保存容量の利用可能枠内に収める。全voxel特徴や全候補ペアの特徴を一括保存しない。

## 成功条件と停止条件

- primary指標: 保存・読み込みを含む反復時の所要時間、保存容量、最大メモリ、特徴・得点の差、同条件の公式combined scoreと最終graphの一致。
- 成功条件: 実験化前に固定した数値許容差と出力の一致条件を満たし、反復時の総費用が下がり、必要な全対象を保存・読み出しできる。ここでの成功は再利用の成立であり精度改善とは呼ばない。
- 必須guard: 窓や変形・座標が変わったら必要な特徴を再抽出する。同一frame番号でも入力窓が違う特徴を流用しない。公開重みの学習来歴と教師対応を保存物に紐付ける。
- 成功時の次段階: 証拠と費用を示してユーザー判断へ渡し、frozen_image_encoderおよび同条件の下流比較へ引き継ぐ。
- 失敗時の停止範囲: 条件や特徴schemaを修正して再評価する。部分保存へ変える場合も、必要な入力が欠けないことと再計算費用を明記し、等価性を満たさないものを共通cacheとして採用しない。

## 実行しないこと

- 禁止する代替実装、proxy、同一OOF上の救済探索: frame単独特徴への置換、異なる窓・重み・座標の混用、得点だけを保存してトラッカー再学習用の特徴と呼ぶこと、特徴不足を教師情報で補うこと。
- 壁打ちで採らなかった案と理由: 全voxel特徴の一括保存は容量未確認のため初期設計から外す。座標補正や画像augmentationを無費用で同じcacheから処理できるとは仮定しない。

## リスク

- leakage / validation: cacheは評価の独立性を作らない。公開モデルが評価胚を学習した場合は固定公開モデル下の条件付きの比較として区別する。
- hidden test: 訓練用に保存した特徴をhidden画像の代用にはできない。提出時はhidden画像から同じ条件で特徴を抽出する必要がある。
- runtime / memory: 候補数、特徴次元、窓数に応じて保存量と読み込み時間が増える。重い候補ペアの中間値まで一括保存せず、必要最小限の特徴と再計算費用を比較する。
- 再現性: 入力一覧、公開モデル版とSHA、前処理・全窓・座標・抽出方法・精度、schema、下流モデル版をmanifestへ記録する。
