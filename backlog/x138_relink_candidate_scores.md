## 入力・予測対象・出力・推論方法

実装区分は`docs/glossary.md`に定義したこのリポジトリ内の管理用ラベルを使う。処理内容と省略点を先に具体的に記録する。

- input: 固定trackerが採点済みの候補ID・得点・保存範囲mask、同一ILP後node/edge、既存の近傍運動参照。
- target / objective: 既存のmotion再接続費用と割当を変えず、得点参照元だけを拡張して正しい親を選ぶ。
- output: 同一node集合上の再接続edgeと得点参照・欠損の監査記録。
- loss: なし。初回は再学習・得点校正をしない。
- decode / 推論方法: 現行の再接続割当と残りの後処理を固定し、ILP選択辺のみの辞書と保存候補辺の辞書を比較する。未計算と真の0点を区別し、欠損時の同条件処理は実装前に確定する。1対1再接続の変更だけで分裂を解決したとはしない。
- 処理単位: 同じ隣接時刻の再接続候補集合と動画全体の後処理。
- 実装区分: 固定モデルの後段を変更する新規案。特定文献の忠実再現ではない。上記の入出力・比較を実験契約へ移し、管理用ラベルは[用語集](../docs/glossary.md)に従う。

## 最小の反証可能な検証

- 検証方法: 学習側保存cacheで、同じnode・幾何候補に対し選択辺のみ/保存全辺の2条件を再生。欠損→得点ありとなった候補数、親順位、変更辺、後段での残存を確認。 保存閾値、得点を取得済みの再接続候補率、再追加nodeへの得点欠損率を別々に計測。全pair保存と称さない。 学習側内部で方式と費用を固定し、反対胚へ適用する両方向の条件付き評価。候補内診断→Kaggleで全動画graphと同じ公式評価器→ラベル非参照の可変動画数・密度・境界・offline推論smoke。既に詳細を分析した20動画を未使用評価と呼ばず、設定選択にも使わない。
- variant / config / fold / booster数: 学習0、得点辞書のみを変える推論2条件。両胚で同じ評価対象を使う。booster数0。
- control再学習: なし。trackerと対照の推論を固定する。
- 想定runtime / resource: 保存範囲内はCPU辞書参照と既存再接続、追加GPU学習0。低得点点の新規採点は別案。全後処理CPU再生の画像/DeepCenter費用は実測する。 [現在の学習方針](KAGGLE_DIRECTION.md#今後の学習方針)のKaggleのみ・週45 GPU時間以内・課金なし・1回12時間以内を引き継ぐ。

## 成功条件と停止条件

- primary指標: 同条件対照との差として両胚の全graph公式combined score、adjusted edge Jaccardとdivision Jaccard。局所指標を公式評価の代用にしない。
- 成功条件: 保存範囲内の同じ再接続候補で実際の選択が改善し、両胚の最終公式combined scoreが対照を上回り、division Jaccardが悪化しない。
- 必須guard: 得点ありへ変わる候補率、再追加nodeの欠損率、親順位・変更辺、既知正解の回収と破壊、後処理後の残存を分ける。保存閾値を示し全pair採点済みと称さない。
- 成功時の次段階: 事前に決める局所進行条件と費用条件を満たしてからKaggleの全graph公式評価へ進む。実験化・採否・完了・submissionは各ユーザー判断に従う。
- 失敗時の停止範囲: 必要候補の得点が保存されていない、実際の割当が変わらない、または未使用側の両胚の最終scoreが改善しない。 局所条件未達なら全graph拡大を止める。再検討条件: 不足scoreの保存方法が定まり、再接続の競合へ有効な候補が届く証拠がある場合。

## 実行しないこと

- 禁止する代替実装、proxy、同一OOF上の救済探索: tracker/ILP費用の再学習・調整、得点clipping、候補範囲やnodeの同時拡張、得点欠損の負例化、外側評価での閾値探索。低得点点の新規採点を黙って追加しない。
- 壁打ちで採らなかった案と理由: exp050は共有得点学習と集合ILP、exp051はILPでの得点上限・費用比較。本案はILP後の得点参照だけ。取得できない得点を距離proxyで代用すると問いが変わる。

## リスク

- leakage / validation: 画像モデルと座標headの学習来歴を含む条件付き比較で、独立CVとは呼ばない。既に分析した20動画を未使用評価へ戻さず、方式・閾値・checkpointの選択は学習側内部に限定する。未知注釈を負例化しない。
- hidden test: 全test動画の画像と固定予測だけを使い、GEFF・正解細胞数・公開testと同じ動画数を使わない。隣接時点edge、娘の親高々1・母の娘高々2。未知入力/時間上限時は合法な元graphへ戻す。保存cacheが必要項目を欠けば取得費用を見積もり、勝手に代用しない。
- runtime / memory: CPU辞書参照中心だが、後処理再生に画像・座標補正が必要なら取得費用を計上する。保存候補量によるメモリと全動画時間を測る。
- 再現性: 入力動画・窓・候補ID・座標・得点と存在mask・重み・source・config・選択結果の版とSHAを保存する。
