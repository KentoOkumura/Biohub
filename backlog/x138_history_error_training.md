## 入力・予測対象・出力・推論方法

- input: 現在の固定検出ID・補正座標・画像特徴、予測履歴の対応ID・座標・特徴・欠測と信頼度。推論で取得できる情報だけを入力する。
- target / objective: GEFFで確認できる現在の接続・分裂。過去の誤った予測を正解教師にはせず、履歴入力の誤りとして扱う。
- output: 対照と同じ接続・分裂得点。合成誤差の種類そのものを当てることを最終目的にしない。
- loss: 選定する履歴trackerの同じ教師mask・接続／分裂損失を全条件で維持する。事前学習と微調整で新しい出力・対照損失を同時に加えない。
- decode / 推論方法: 対照と同じ候補生成・構造制約・後処理。履歴は実際の予測から作り、短い・欠けた履歴も学習時と同じ表現で処理する。
- 処理単位: 隣接2-frameを予測する過去履歴付き候補集合。履歴長・集約・逆方向採点の契約は先行するtracker設計から固定して継承する。
- 実装区分: 実誤差の測定、合成履歴での事前学習、実予測履歴での微調整までを中核とする。独立な座標jitterだけの試行をこの案全体の実装と呼ばない。

## 誤履歴を作る範囲

- 学習側だけから、位置ずれの方向・持続時間・時間相関・近傍相関、連続欠落、対応の取り違え、分裂前後の誤りを測る。測定できる既知注釈範囲と、未知領域の限界を明示する。
- 実例の誤履歴を再利用するか、確認した分布から連続した誤りを作る。平均中心距離1.516 µmを独立Gaussianの標準偏差に置き換えない。中心のbiasが時間差分で相殺される場合と、補正の揺れが増幅する場合を分ける。
- 取り違えはID・座標・対応する画像特徴を整合させ、単なる数値ノイズと区別する。座標を変更した位置の画像特徴が必要なら再取得する。現在の候補・教師まで暗黙に変えない。
- 正解履歴は追加情報の上限診断に限る。実際の学習・検証で、評価対象の教師から作った履歴を入力しない。

## 親実験からの差分

- 変更するもの: 履歴の誤りを含む学習データの生成と、合成から実予測への学習順序。
- 固定するもの: detector・画像encoder・座標head、現在の検出ID・特徴、履歴trackerの構造・出力・損失・分割・推論。更新数を揃えた対照を用意する。
- 再利用するコード / config / 生成物: exp043入力と、exp035の対象sampleを除く履歴生成・誤履歴診断の考え方。旧cache・旧tracker重みを新入力の対照へ流用しない。
- 新しく作るもの: 学習側の履歴・残差の測定表、整合した誤履歴生成、事前学習と微調整、入力来歴の検証、同条件の実履歴対照。

## 最小の反証可能な検証

- 検証方法: まず追加情報の上限診断と実履歴での劣化を分ける。その後、同じtrackerで実履歴のみ、合成誤履歴のみ、合成事前学習後に実履歴で微調整を比較し、全条件を実予測履歴で評価する。
- variant / config / fold / booster数: 基本案は3条件・外側2方向、booster数0。学習側の履歴生成用モデルを別に数え、同じ総更新数の対照と費用を契約に記す。
- control再学習: 同じ新入力・履歴契約・更新数の実履歴対照がなければ必要。予測履歴は対象動画を学習から除いたモデルから作る。これをout-of-fold（OOF、学習外の分割への予測）と呼ぶ対象は履歴生成器に限定する。
- 想定runtime / resource: Kaggleのみ、週45 GPU時間以内・課金なし・1回12時間以内。特徴抽出、分割外履歴生成、事前学習、微調整、全graphを全て含める。履歴モデルの費用を隠してtracker単体時間だけを報告しない。

## 成功条件と停止条件

- primary指標: 実予測履歴での両胚の既知接続回収、判定可能な誤接続、分裂回収と母数。最終確認は公式combined score。
- 成功条件: 同じ更新数の実履歴対照より両胚の接続を改善し、分裂を落とさず、事前に定める誤接続条件を満たす。合成データ上の改善だけを成功としない。
- 必須guard: 未注釈を負例にしない。誤差分布・モデル選択・微調整量を外側胚から決めない。正しい履歴／誤履歴／履歴なしを分け、単に履歴を無視した効果と区別する。
- 成功時の次段階: 単体進行条件と費用を満たした場合だけ全graphを評価し、採否・完了をユーザーへ示す。submissionは別の明示承認に従う。
- 失敗時の停止範囲: 正解履歴に追加情報がない、学習内にも適合しない、実履歴へ移らない、誤接続や分裂を悪化させる場合は大規模化を止める。

## 実行しないこと

- 禁止する代替実装、proxy、同一OOF上の救済探索: 正解履歴だけの学習・評価、評価胚の残差での誤差生成、独立Gaussianだけを実誤差と呼ぶこと、合成事前学習だけで微調整を省くこと、画像モデルの更新。
- 壁打ちで採らなかった案と理由: 予測履歴を使うだけの再実行はexp035との差を説明できない。attention方式を変えるだけで誤履歴の問題が解決するとは仮定しない。実残差が未回収でも設計議論は進めるが、分布を創作して学習しない。

## リスク

- leakage / validation: 履歴のOOFと座標head・公開画像重みの独立性は別。最終headを固定するなら教師への露出を含む条件付き比較と明示し、headも胚外にする評価を主張するならその再生成契約を別に定める。
- hidden test: 分裂直後、境界、連続欠落、初期frameでも実予測から履歴を作れること。正解の細胞数や完全な履歴を仮定しない。
- runtime / memory: 履歴生成用の複数モデルと長い誤り系列の保存費用を測る。学習時の追加費用と提出推論費用を分ける。
- 再現性: 履歴生成器・分割・教師露出、乱数、誤差分布、破壊したID・時点、微調整前後重み、入力特徴のSHAを保存する。

## 未決事項

- 基準とする履歴trackerの構造・履歴長・出力契約。既存候補から継承する場合はその設計を確定し、未実装のモデルを存在すると扱わない。
- 合成誤履歴の生成規則、各誤りの混合、未知履歴・分裂後・逆方向の扱い。数値分布は学習側で測る。
- 履歴生成器の分割と総モデル数、固定最終headの条件付き評価かheadも学習外にするか、事前学習と微調整の更新配分。
- checkpoint選択、誤接続の許容量、全graphへの進行条件。未測定の精度・費用・SHAは別の実行時確認事項。
